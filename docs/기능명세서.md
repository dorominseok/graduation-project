# 기능 명세서
### 운동 습관 분석 기반 맞춤 루틴 추천 헬스 웹앱(PWA)

> 작성 목적: 졸업작품 계획서용 기능 명세
> 플랫폼: PWA(웹앱, 폰 홈 화면 설치 가능) / 모바일 우선 반응형
> 우선순위: **기본 기능** / **핵심 기능** / **추가 기능**

---

## 1. 기본 기능 — 앱이 돌아가기 위한 토대

기존 헬스 기록 앱도 갖춘 기능. 차별점은 아니지만, 이 기록 데이터가 있어야 분석과 추천이 가능하므로 **핵심 기능의 전제 조건**이다.

| 기능 | 설명 | 우선순위 |
|---|---|---|
| 회원가입 / 로그인 | 이메일 기반 가입, 인증, 세션 관리 | 기본 |
| 프로필 | 훈련 목표 (근력 / 근비대 / 지구력 / 일반 체력) | 기본 |
| 운동 기록 | 세션 단위 기록. 세트별 중량·횟수 입력, 완료 체크로 저장, 운동 시간 자동 산출 | 기본 |
| 운동 히스토리 | 과거 운동 기록 조회, 날짜별/종목별 필터, 수정·삭제·사후 입력 | 기본 |
| 통계 | 부위별 볼륨 그래프, 운동별 추정 1RM 추이, 세트별 강도(%) | 기본 |
| 운동 종목 DB | 종목별 주동근·밀기당기기·측정 유형(measure_type) 정보 제공 | 기본 |

> 부상 부위·보유 기구 등 개별 제약은 입력받지 않는다. 진입장벽을 낮추고, 개별 사정은 루틴 후보정(2.4)으로 조정하도록 한다.
> 프로필은 **훈련 목표 1종**이다. 운동 경력(LOG-11)에 이어 키·체중도 제외하였다. 어떤 로직도 참조하지 않고, 프로필 컬럼은 필요해질 때 추가해도 비용이 같아 미리 확보할 이유가 없기 때문이다. 목표만 남긴 것은 루틴의 반복 횟수·강도 범위를 정하는 축이라 출력 형식(2.1)이 그 값을 요구하기 때문이다. (LOG-11, LOG-13)

### 1.1 운동 기록 상세

분석과 추천이 모두 기록 데이터 위에서 동작하므로, 기록 기능은 기본 기능이면서 실질적으로는 핵심 기능의 전제이다. 상세 설계는 **「운동기록_방식_설계서.md」** 를 따르며, 요지는 다음과 같다.

| 항목 | 내용 |
|---|---|
| 데이터 구조 | 세션(한 번의 운동) — 세트(개별 수행)의 2계층. 하루 여러 세션 허용 |
| 저장 단위 | 세트 1개 = 1행. 세트별 중량·횟수를 개별 저장 |
| 입력 화면 | 세트 행 + 완료 체크 방식. 루틴 수행과 자유 기록이 같은 화면을 사용 |
| 저장 시점 | 완료 체크한 세트만 저장. 루틴에서 미리 표시된 행은 계획일 뿐 기록이 아님 |
| 입력 부담 완화 | 종목 선택 시 직전 기록 자동 채움 / 세트 추가 시 직전 세트 복사 / 루틴 프리필 |
| 워밍업 | 선택적 표시(기본 미표시). 표시된 세트는 볼륨 집계에서 제외 |
| 운동 시간 | 세트 저장 시각으로 자동 산출(별도 조작 없음). 이상치 보정 규칙 적용 |
| 누락·수정 | 미완료 세션 이어쓰기, 과거 기록 사후 입력, 수정·삭제 허용 |
| 종목 유형 | 중량·횟수 / 맨몸 / 중량 추가 맨몸 / 시간 기반 4종으로 입력 항목 분기 |

## 2. 핵심 기능

### 2.1 오늘의 루틴 추천
- **설명**: 운동하려는 시점에 그때까지의 기록을 분석해, 약점을 보완하는 오늘의 루틴을 생성
- **입력**: 유저 운동 기록(최근 4주)
- **출력**: 오늘의 루틴 (운동명 · 세트 · 반복 횟수 · 순서) — 유저 후보정 가능
- **처리 흐름**:
  1. 운동 기록을 주동근 기준으로 부위별 분류·집계 (자체 로직)
  2. 약점·불균형 판정 (2.2 참조) 및 보완 우선순위 산출
  3. 운동 종목 DB에서 대상 부위의 운동 후보를 조건 조회
  4. 분석 결과와 후보를 LLM에 전달해 루틴 구성 요청 (후보 목록 내에서만 선택하도록 제한)
  5. 생성 결과를 정량 규칙으로 검증(2.3)한 뒤 유저에게 제공
- **기술**: 자체 분석 로직 + DB 조건 조회 + LLM API + 규칙 검증
- **근거**: ACSM 2026 근력운동 가이드라인
- **실패 대응**: LLM 호출 실패 또는 검증 반복 실패 시 규칙 기반 기본 루틴으로 대체
- **우선순위**: **핵심 기능 (최우선)**

### 2.2 약점·불균형 분석
- **설명**: 운동 기록에서 부위별 부족·과다와 근육군 간 불균형을 판정
- **집계 방식**: 최근 4주 기록을 주동근 기준으로 부위별 집계 → 주당 평균 세트로 환산
  - 판정 단위는 `primary_muscle` 기반 **9종**(가슴·등·어깨앞·어깨뒤·삼두·이두·앞허벅지·뒤허벅지둔근·코어). 종아리·전완은 판정 대상에서 제외하고 표시만 한다
  - 화면은 상위 6종(가슴·등·어깨·팔·하체·코어) / 하위 9종의 2계층으로 표시하며, 판정 라벨은 하위에만 붙인다
  - 집계 대상: **완료된 세션의 본세트만**. 워밍업으로 표시된 세트는 제외한다 (ACSM 기준이 본세트 기준이므로 단위를 맞추기 위함)
  - 사후 입력된 기록은 볼륨 집계에 포함한다 (실제 수행한 운동이므로)
- **부족·과다 판정 (ACSM 기반, 4단계)**:
  - 주 4세트 미만 → 부족
  - 주 4세트 이상 10세트 미만 → 권장 이하
  - 주 10세트 이상 20세트 이하 → 최적
  - 주 20세트 초과 → 과다
- **불균형 판정**:
  - 밀기(가슴·전면어깨·삼두) vs 당기기(등·후면어깨·이두)
  - 상체 vs 하체
  - 한쪽이 다른 쪽의 **2배를 초과**하면 불균형으로 판정
- **강도 측정(별도 축)**: 기록으로부터 추정 1RM을 산출해 세트별 강도(%)를 계산. 현황을 표시할 뿐 강도 권고(처방)는 하지 않는다. 산출 대상은 중량·횟수를 기록하는 종목의 `반복 12회 이하` 세트로 한정하며, 하루 여러 세트 중 최댓값을 그날의 값으로 채택한다.
- **출력**: 부족·불균형 부위 목록 → 추천의 근거 및 분석 결과 화면에 사용
- **우선순위**: **핵심 기능**

> 빈도 판정(주요 근육군 주 2회 이상 자극)은 볼륨 판정 완성 후 여유가 있을 때 추가하는 항목으로 둔다.

### 2.3 추천 품질 검증
- **설명**: 생성된 루틴이 규칙에 맞는지 자동 검사
- **검사 항목**:
  - 부위별 세트 수가 권고 범위 내에 있는가
  - 밀기·당기기, 상·하체 볼륨이 한쪽으로 치우치지 않았는가
  - 제공한 후보 목록과 분석이 정한 세트 수를 준수하였는가
- **실패 시**: 최대 N회 재생성 요청 → 계속 실패하면 규칙 기반 기본 루틴으로 대체
- **출력**: 통과/실패 및 통과율(%) → 검증 계획의 정량 지표로 활용
- **우선순위**: **핵심 기능**

### 2.4 루틴 후보정
- **설명**: 생성된 루틴을 유저가 자신의 상황에 맞게 조정
- **기능**: 운동 교체, 세트·횟수 조정
- **대체 후보 선정 기준**: 같은 부위(`body_part`)이면서 **기구(`equipment`)가 다른** 종목을 우선 제시한다. 부위만으로 후보를 고르면 기구 사용 불가·부상 등 실제 교체 사유를 해소하지 못하기 때문이다. (LOG-08)
- **의의**: 부상·보유 기구 등 개별 제약을 사전에 입력받지 않는 대신, 결과를 유저가 직접 조정하도록 한다
- **성격**: 추천 루틴은 확정된 정답이 아니라 근거 있는 초안으로 제공. 후보를 제시할 뿐 최종 선택은 유저가 한다
- **한계**: 기구가 다르다고 항상 대체 가능한 것은 아니다. 특정 동작 자체를 피해야 하는 경우는 해소되지 않으므로, 후보 제시는 보조 수단으로 둔다
- **우선순위**: **핵심 기능**

### 2.5 뱃지 시스템
- **설명**: 목표 달성 시 뱃지 지급, 프로필 전시 요소
- **예시 뱃지**: 3대 500 / 3대 450 / 3대 300 / 스쿼트 100회 / 덤벨컬 20kg 등
- **처리**: 운동 기록 저장 시 누적 기록을 달성 조건과 비교 → 충족 시 자동 지급 (단순 판정 로직)
- **표시**: 프로필에 획득 뱃지 전시, 미획득 뱃지는 목표로 표시
- **우선순위**: **핵심 기능**

### 2.6 친구 그룹 (활동 공유)
- **설명**: 지인 그룹 단위로 서로의 운동 활동을 공유·확인하여 동기부여
- **그룹 방식**: 코드/초대 기반
  - 그룹 생성 시 고유 초대코드 발급
  - 친구가 코드 입력 → 그룹 참여
  - (확장 시 아이디 검색 방식 추가 가능)
- **활동 공유**: 그룹 멤버별 주간 활동 현황 표시 (주 운동 횟수, 총 운동 시간)
  - 주 운동 횟수 = 해당 주의 완료 세션 수 (사후 입력 기록 포함)
  - 총 운동 시간 = 세션별 자동 산출 시간의 합. 사후 입력 세션은 시간이 부정확하므로 합계에서 제외한다
- **성격**: 승부를 가리는 경쟁이 아니라, 서로의 활동이 보이는 것 자체가 자극이 되는 상호 확인 방식
- **데이터 구조(초안)**:
  - `groups (id, name, invite_code, created_by)`
  - `group_members (group_id, user_id, joined_at)`
  - 활동 현황은 `workout_sessions`를 주 단위로 집계해 산출 (별도 집계 테이블 없음)
- **우선순위**: **핵심 기능**

## 3. 추가 기능 — 여유 시 구현

### 3.1 푸시 알림
- **설명**: 운동 습관 유지를 돕는 알림
- **예시**: 미운동 알림 / 연속 운동 일수 끊김 경고 / 약점 부위 보완 제안
- **특징**: 약점 분석 결과와 연동해 개인화
- **기술**: FCM(Firebase Cloud Messaging) + 서버 스케줄러
- **PWA 참고**: 알림 권한 요청 가능. iOS는 홈 화면 설치 시 알림 수신
- **정시 알림**: 기기 스케줄링 대신 서버 스케줄러가 시간을 판단해 푸시 발송
- **UX**: 알림 빈도 조절 / 끄기 옵션 제공
- **우선순위**: **추가 기능 (핵심 완성 후, 기본형부터)**

## 4. 우선순위 요약

| 구분 | 기능 | 완성 목표 |
|---|---|---|
| 기본 | 회원/프로필/기록/히스토리/통계/종목DB | 반드시 완성 |
| 핵심 | 오늘의 루틴 추천, 약점·불균형 분석, 품질 검증 | 반드시 완성 (최우선) |
| 핵심 | 루틴 후보정, 뱃지, 친구 그룹(활동 공유) | 완성 |
| 추가 | 푸시 알림 | 여유 시 |

> **범위 원칙**: 미완성 다수 기능보다 완성된 핵심 기능이 우선.
> 루틴 추천과 약점 분석을 가장 깊게 구현하고, 나머지는 동작하는 수준으로 완성한다.

## 5. 검증 계획

- **정량 검증**: 추천 루틴의 운동학적 기준 통과율 측정
- **실사용자 검증**: 지인 약 10명 배포 → 루틴 만족도 / 실제 수행률 / 4주 후 부위 균형 개선 여부 수집
- **수행률 산출 방식**: 별도 로깅 없이 기록 구조에서 산출한다. 세션에 연결된 루틴의 계획 세트 수를 분모로, 실제 저장된 세트 수를 분자로 계산한다(완료 체크한 세트만 저장되므로 저장된 세트 수가 곧 수행량). 루틴 후보정이 있었다면 후보정 이후의 계획을 분모로 삼는다.
