# 루틴 생성 로직 설계서
### 운동 습관 분석 기반 맞춤 루틴 추천 헬스 웹앱 — 오늘의 루틴 추천 설계

> 본 문서는 핵심 기능 「오늘의 루틴 추천」(기능명세서 2.1·2.3·2.4, UC-03-03~06)의 생성 규칙, LLM의 역할, 검증, 저장 구조, 측정 지표를 확정한 것이다.
> 분석 로직(「운동_분석로직_설계서」)이 낸 판정을 입력으로 받고, LLM 통제 방식은 「LLM_연동_실험기록」의 결론을 따른다.
> 작성 시점: 2026-10-24 (구현 착수 직전). 결정 과정은 「설계변경_로그」 LOG-40.

---

## 0. 설계 개요

### 0.1 원칙

1. **판정과 수치는 자체 로직이 확정한다. LLM은 조합과 설명만 한다** (LLM 실험기록 0.3).
   어느 부위를 몇 세트 할지는 규칙이 정한다. LLM은 부위마다 주어진 후보 안에서 종목을 고르고, 순서를 정하고, 조합 이유를 한두 문장으로 쓴다. LLM 출력에는 숫자 필드가 하나도 없다.
2. **루틴은 정답이 아니라 근거 있는 초안이다** (기능명세서 2.4). 사용자는 후보정으로 바꿀 수 있고, 루틴 없이 기록해도 된다.
3. **LLM이 없어도 루틴은 나온다.** 규칙 기반 루틴이 먼저 완성되고, LLM은 그 위에서 종목 선택만 대신한다. LLM이 실패하면 규칙 루틴이 그대로 나간다.
4. **강도는 처방하지 않는다** (분석 설계서 1.3). 반복 범위만 측정 유형으로 정하고, 중량은 지난 기록에서 채운다.
5. **바꾸기 비싼 것은 고정하고, 숫자는 설정값으로 둔다.** 저장 구조·LLM 역할·지표 정의는 여기서 확정하고, 세트 수·가중치·후보 수 같은 수치는 초기값과 근거만 적어 `app.routine.*`로 뺀다(12장). 실험(11장)으로 조정한다.

### 0.2 전체 흐름

```
[홈] 오늘 루틴 추천받기
  │
  ├─ 1. 분석 (기준일 = 어제)            부위별 주당 세트·판정·균형      ← 분석 설계서
  ├─ 2. 오늘 할 부위와 세트 (규칙)       우선순위 → 부위별 세트 → 하루 총량   (2·3장)
  ├─ 3. 부위별 후보 종목 (규칙)          즐겨찾기 → 해 본 종목 → 새 종목     (4장)
  ├─ 4. 종목 선택·순서·설명 (LLM)        후보 안에서만, 숫자 없음            (5장)
  │     └─ 검증 실패 → 최대 2회 재요청 → 그래도 실패 → 규칙 선택(7장)
  ├─ 5. 세트·반복 범위 채우기 (규칙)                                       (6장)
  └─ 6. 저장 · 표시                     하루 1개                          (9장)
        │
        ├─ 후보정: 종목 교체 · 세트 조정 · 종목 빼기                         (8장)
        ├─ 이 루틴으로 기록 → 기록 화면에 계획 카드                          (10장)
        └─ 만족도 (세트를 체크한 날)                                       (11장)
```

## 1. 입력

### 1.1 분석 결과 — 기준일은 어제

`GET /analysis/muscle-volume`, `/analysis/balance`와 같은 계산을 **기준일 = 어제**로 돌린다(LOG-39).

| 쓰는 값 | 출처 | 용도 |
|---|---|---|
| 판정 부위 9종의 주당 평균 세트·판정 | 분석 2.1~2.3 | 우선순위(2장) |
| 밀기/당기기 · 상체/하체 판정 | 분석 4장 | 우선순위 보정(2.3) |
| 판정 신뢰도 (`workoutDayCount`) | 분석 8.2 | 기록이 적을 때 안내(2.6) |

> **오늘이 아니라 어제인 이유**: 하루 기록은 종료가 없어 오늘 체크한 세트가 바로 분석에 들어간다. 기준일을 오늘로 두면 루틴을 받은 뒤 한 세트만 해도 판정이 달라져, 같은 날 같은 루틴의 근거가 바뀐다. 루틴은 "어제까지의 나"를 보고 짠다.

### 1.2 기록에서 직접 읽는 값

분석 응답에 없는 값은 기록에서 읽는다.

| 값 | 정의 | 용도 |
|---|---|---|
| **부위별 마지막 운동일** | 그 판정 부위에 본세트가 있는 가장 최근 날짜. **오늘 포함** | 회복 제외(2.2), 정렬(2.3) |
| **주당 운동 일수** | 분석 집계 구간(기준일 포함 28일, 기록이 짧으면 `basisDays`)에서 운동한 날 수 × 7 ÷ 구간 일수 | 부위당 세트(3.1) |
| 종목별 수행 횟수 | 최근 8주 그 종목을 기록한 날 수 | 후보 순서(4장) |
| 즐겨찾기 | `user_favorite_exercises` | 후보 순서(4장) |

회복 제외만 오늘 기록을 본다. 오늘 이미 가슴을 하고 루틴을 받으면 가슴은 빠져야 하기 때문이다.

## 2. 오늘 할 부위 — 우선순위

### 2.1 대상

판정 부위 9종(가슴·등·어깨 전·측면·어깨 후면·삼두·이두·앞허벅지·뒤허벅지·둔근·코어). 종아리·전완은 분석에서 판정하지 않으므로 루틴에도 넣지 않는다(분석 2.3).

| 판정 | 루틴 |
|---|---|
| 부족 · 권장 이하 | **우선 후보** |
| 최적 | 하루 총량을 못 채울 때만 (2.5) |
| 과다 | **넣지 않는다** |

### 2.2 회복 제외

**최근 48시간(오늘·어제) 안에 본세트를 한 부위는 뺀다.**

어제 가슴을 했는데 가슴이 여전히 "부족"이라는 이유로 오늘 또 넣으면 따르기 어려운 루틴이 된다. 48시간은 같은 근육군을 연속해서 하지 않는 일반적인 회복 간격이며 설정값이다(`recovery-hours`).

### 2.3 정렬

남은 후보를 다음 순서로 세운다.

1. **판정**: 부족 → 권장 이하
2. **모자란 양**: `10 − 주당 평균 세트` 가 큰 순 (10 = 최적 하한, 분석 2.2)
3. **마지막 운동일**: 오래된 순. 한 번도 안 한 부위가 가장 오래된 것이다
4. **크기**: 모든 조건이 같으면 고정 순서 — 가슴 → 등 → 앞허벅지 → 뒤허벅지·둔근 → 어깨 전·측면 → 어깨 후면 → 삼두 → 이두 → 코어

**균형 보정**: 밀기/당기기나 상체/하체가 불균형(2배 초과, 분석 4.2)이면, **적은 쪽에 속한 부위를 같은 판정 안에서 앞으로 당긴다.** 판정을 뛰어넘지는 않는다 — "부족"인 밀기 부위가 "권장 이하"인 당기기 부위보다 앞선다. 불균형은 부족을 메우는 과정에서 함께 줄어드는 것이 목표이고, 판정 체계를 뒤집지 않는다.

> **마지막 운동일을 정렬에 넣은 이유**: 같은 판정·비슷한 부족량이면 오래 쉰 부위가 회복을 마쳤을 가능성이 크고, 원래 다음 차례였던 부위다. 이를 먼저 하면 사람마다 있는 운동 주기가 꼬이지 않는다.

### 2.4 담기

정렬된 순서대로 부위를 담는다. 부위마다 세트 수는 3.1로 정하고, **하루 총량 상한(18세트)을 넘지 않을 때만** 담는다. 넘으면 그 부위는 건너뛰고 다음 부위를 본다.

### 2.5 하루 총량을 못 채울 때

담은 세트가 **하한(12세트)에 못 미치면**, 남은 **최적 부위 중 마지막 운동일이 가장 오래된 부위**부터 채운다(회복 제외는 그대로). 그래도 모자라면 짧은 루틴으로 둔다.

> **판정이 아니라 마지막 운동일로 채우는 이유**: 최적 부위를 판정 순으로 채우면 잘 돌고 있던 부위를 오늘 당겨 오게 되고, 그 부위는 다시 48시간 밀린다. 가장 오래 쉰 부위를 가져오면 원래 다음 차례를 앞당기는 것이라 주기가 흐트러지지 않는다. (사용자 검토에서 정함 — LOG-40)

### 2.6 기록이 없거나 적을 때

별도 입문 루틴을 두지 않는다. 위 규칙에 기본값 두 개만 넣는다.

- **주당 운동 일수를 모르면 3일로 본다** (`default-days-per-week`).
- 기록이 없으면 모든 부위가 "부족 · 주 0세트 · 한 번도 안 함"으로 같아서 2.3의 4번(크기 순)이 순서를 정한다.

그러면 규칙만으로 다음이 나온다.

| 날 | 결과 |
|---|---|
| 첫날 | 가슴 4 · 등 4 · 앞허벅지 4 · 뒤허벅지·둔근 4 = 16세트 (다음 부위를 담으면 18을 넘어 멈춤) |
| 다음 날 | 어제 4부위는 회복 제외 → 어깨 전·측면 · 어깨 후면 · 삼두 · 이두 · 코어 |
| 셋째 날 | 첫날 부위가 회복을 마쳐 다시 큰 근육 |

신규 사용자용 규칙 없이 **큰 근육 / 작은 근육 분할**이 생기고, 기록이 쌓이면 부족한 부위 위주로 옮겨 간다. 판정 신뢰도가 낮으면(분석 5.5) 루틴 위에 "기록이 쌓일수록 내 약점에 맞춘 루틴이 돼요"를 띄운다. 추천 자체는 막지 않는다 — 검증 첫날부터 핵심 기능을 써 볼 수 있어야 한다.

## 3. 세트 수

### 3.1 부위당 세트

```
기본값 = 주 목표 10세트 ÷ 주당 운동 일수

부족       → ⌈기본값⌉
권장 이하  → ⌊기본값⌋
최적(채움) → ⌊기본값⌋, 단 최대 3

모든 경우 2세트 이상 6세트 이하로 자른다
```

| 주당 운동 일수 | 기본값 | 부족 | 권장 이하 |
|---|---|---|---|
| 2 | 5.0 | 5 | 5 |
| 3 | 3.3 | 4 | 3 |
| 4 | 2.5 | 3 | 2 |
| 5 | 2.0 | 2 | 2 |

**근거**: 판정 기준(주 10~20세트)은 **한 주** 단위다. 이 사람이 주당 운동 일수만큼 비슷한 루틴을 따르면 부위당 주 10세트 근처가 된다 — 부족한 부위를 최적 하한까지 끌어올리는 양이다. 부위당 한 번에 6세트를 넘기지 않는 것은 한 세션에서 한 근육에 쓸 수 있는 실효 세트가 그 언저리에서 줄어들기 때문이고, 2세트 미만은 종목 하나로 의미 있는 자극이 되기 어렵다.

### 3.2 하루 총량

**12~18세트** (`daily-min-sets`, `daily-max-sets`). 세트당 2~3분(휴식 포함)이면 약 40~60분이다.

### 3.3 예시 — 주 3회 운동하는 사람

| 부위 | 최근 4주 주당 | 판정 | 모자란 양 | 오늘 |
|---|---|---|---|---|
| 어깨 후면 | 0 | 부족 | 10 | 4 |
| 삼두 | 2 | 부족 | 8 | 4 |
| 가슴 | 4 | 권장 이하 | 6 | 3 |
| 앞허벅지 | 6 | 권장 이하 | 4 | 3 |
| 등 | 12 | 최적 | — | 제외 |
| **합계** | | | | **14** |

### 3.4 세트 수를 LLM에 맡기지 않는 이유

- **재현성**: 같은 기록이면 같은 세트 수가 나와야 검증(6장)이 의미가 있다.
- **직렬화 결함**: 운영 모델(`gemini-3.5-flash-lite`)은 구조화 출력의 숫자 필드가 약 7.5% 깨졌다(LLM 실험기록 7.4). 세트 수를 서버가 채우면 이 결함이 루틴에 들어올 길이 없다.
- **설명 가능성**: "주 3회 하시니 10세트를 나눠 오늘 4세트"를 화면에 그대로 보여 줄 수 있다.

## 4. 후보 종목

### 4.1 부위별 후보 — 최대 5개

부위마다 그 판정 부위에 속한 종목(분석 2.3의 `primary_muscle` 매핑, 어깨는 `delt_region`) 중에서 아래 순서로 채운다.

1. **즐겨찾기한 종목**
2. **해 본 종목** — 최근 8주에 기록한 종목, 자주 한 순. **최대 3개**
3. **안 해 본 종목** — 남은 자리를 채운다
   - **계열(`group_name`)이 겹치지 않는 것 먼저**: 디클라인·인클라인·플랫 벤치프레스가 후보를 다 차지하지 않게
   - 그 안에서 **이미 들어간 후보와 기구(`equipment`)가 다른 것 먼저** (LOG-08과 같은 이유)
   - **자리가 남으면 계열이 겹쳐도 채운다** — 어깨 후면은 세 종목이 모두 한 계열(리어델트)이라, 계열당 하나로 끊으면 후보가 하나뿐이었다(오프라인 실험 준비 중 발견, LOG-41)
   - 같은 조건이면 **입문 대표 종목(`starter_rank`)이 먼저**, 나머지는 시드 순서

**입문 대표 종목.** 기록·즐겨찾기가 없으면 3번만으로 후보가 정해지는데, 시드 순서(영문 이름 순)대로 두면 처음 운동하는 사람의 첫 루틴이 디클라인 벤치프레스·친업·케이블 데드리프트로 나왔다. 그래서 부위마다 입문자가 먼저 익힐 종목을 1~2개 정해 `exercises.starter_rank`(V11, 값은 CSV)에 두었다. 입문 루틴 실례(지인이 운동을 처음 시작할 때 받은 주 5일 루틴)의 종목을 바탕으로 하고, 거기에 없던 어깨 후면·뒤허벅지·둔근을 채웠다. 업라이트 로우는 어깨 충돌 위험 때문에, 일반 데드리프트는 자세를 먼저 배워야 해서 넣지 않았다.

| 부위 | 1순위 | 2순위 |
|---|---|---|
| 가슴 | 바벨 벤치프레스 | 푸시업 |
| 등 | 랫풀다운: 와이드 그립 | 시티드 케이블 로우 |
| 어깨 전·측면 | 덤벨 숄더프레스 | 덤벨 사이드 레터럴 레이즈 |
| 어깨 후면 | 페이스풀 | — |
| 앞허벅지 | 바벨 스쿼트 | 덤벨 런지 |
| 뒤허벅지·둔근 | 루마니안 데드리프트 | — |
| 이두 | 덤벨 컬 | — |
| 삼두 | 케이블 푸시다운 | — |
| 코어 | 플랭크 | 케이블 크런치 |

즐겨찾기·해 본 종목은 앞지르지 않는다. 기록이 쌓이면 자연히 그 사람의 종목으로 바뀐다. 기록이 없는 사람의 첫날 루틴은 **바벨 벤치프레스 · 랫풀다운 · 바벨 스쿼트 · 루마니안 데드리프트**(각 4세트)가 된다. 교체 후보(8장)도 같은 기구·같은 빈도끼리는 입문 대표 종목을 먼저 보인다.

| 부위 | 종목 수 (시드 109종) |
|---|---|
| 가슴 | 18 |
| 등 | 17 |
| 코어 | 16 |
| 삼두 | 14 |
| 앞허벅지 | 11 |
| 어깨 전·측면 | 10 |
| 이두 · 뒤허벅지·둔근 | 각 7 |
| **어깨 후면** | **3** — 후보도 최대 3개 |

**근거**
- **LLM에 넘기는 목록이 작아진다.** 부위 4~5개 × 5 = 최대 25개라 스키마의 종목 열거(enum)가 비대해지지 않는다(LLM 실험기록 8절 미해결 사항).
- **익숙함과 새로움을 같이 준다.** 해 본 종목만이면 루틴이 매일 같고, 새 종목만이면 따라 하기 어렵다.
- **기구 제약은 묻지 않는다.** 기구가 다른 후보가 섞여 있고, 맞지 않으면 후보정(8장)에서 바꾼다(기능명세서 2.4의 원칙).

### 4.2 처음 하는 종목 표시

루틴 항목마다 **`firstTime`**(오늘 이전에 이 종목 세트가 하나도 없음)을 서버가 계산해 저장한다. 직전 수행 기록(명세 5.5)과 같은 조건이라, 중량이 채워지지 않는 종목에 정확히 붙는다.

- 화면은 [처음] 표시와 함께 지난 기록 자리에 **"동작 보기"**(종목 상세의 동작 그림)를 둔다.
- "가벼운 무게로 시작하세요" 같은 강도 안내는 넣지 않는다(원칙 4).
- 저장해 두면 **새 종목 수행률**과 **익숙한 종목 수행률**을 따로 셀 수 있다(11장) — 추천이 새 운동을 시도하게 만드는지 보는 지표다.

## 5. LLM — 종목 선택·순서·설명

### 5.1 LLM에게 주는 것과 받는 것

**주는 것** (user 메시지, JSON)

```json
{
  "slots": [
    { "slot": "DELT_REAR", "label": "어깨 후면", "sets": 4,
      "candidates": [
        { "exerciseId": "68", "name": "페이스풀", "equipment": "케이블", "favorite": false, "firstTime": true },
        { "exerciseId": "69", "name": "덤벨 리어델트 플라이", "equipment": "덤벨", "favorite": false, "firstTime": false }
      ] },
    { "slot": "TRICEPS", "label": "삼두", "sets": 4, "candidates": [ "…" ] }
  ]
}
```

- `sets`는 참고로만 준다(5세트 이상이면 두 종목으로 나눌 수 있다는 판단용). LLM은 숫자를 돌려주지 않는다.
- 슬롯은 **큰 근육 순서**로 준다. 우선순위 순서로 주면 그 순서를 운동 순서로 베끼기 쉽다.
- `exerciseId`는 **문자열**이다 — 스키마 enum은 문자열만 받고, 숫자 필드를 아예 두지 않기 위해서다.
- 후보 순서는 4.1의 순서(즐겨찾기 → 해 본 종목 → 새 종목) 그대로다.

**받는 것** (구조화 출력, `responseSchema`)

```json
{
  "items": [
    { "slot": "CHEST",     "exerciseId": "5" },
    { "slot": "TRICEPS",   "exerciseId": "90" },
    { "slot": "DELT_REAR", "exerciseId": "68" }
  ],
  "comment": "무게를 많이 쓰는 가슴 운동을 먼저 두고, 어깨 후면은 가벼운 케이블 운동으로 마무리하도록 배치했어요."
}
```

| 필드 | 제약 |
|---|---|
| `items[]` | **배열 순서 = 운동 순서**. 슬롯마다 1~2개 (`propertyOrdering`으로 `items` 다음에 `comment` — 고른 뒤에 설명하게) |
| `items[].slot` | 문자열 enum = 이번 요청의 슬롯 키 |
| `items[].exerciseId` | 문자열 enum = 이번 요청의 전체 후보 ID. 슬롯과 맞는지는 6장에서 검사 |
| `comment` | 한국어 1~2문장, 120자 이하. **숫자 금지** |

> **숫자 필드를 없앤 이유**: 세트 분할(5세트를 3+2로)까지 LLM이 숫자로 주면 직렬화 결함이 다시 들어온다. LLM은 "이 슬롯에 종목 둘"만 정하고, 서버가 슬롯 세트를 앞 종목부터 고르게 나눈다(규칙 선택과 같은 `RuleComposer.split`). 오프라인 실험 157회 호출에서 직렬화 결함 **0건**(실험 ①은 호출당 ~7.5%) — LLM 실험기록 11절.

### 5.2 프롬프트 (system, 요지)

실험 ①의 v3 구조(금지 규칙 + 커버리지 규칙)를 따른다. 오프라인 실험으로 **r2를 확정**했다(전문은 `RoutinePrompt.SYSTEM`, 실험 결과는 LLM 실험기록 11절).

- 각 슬롯의 후보 **안에서만** 고른다. 후보 밖 종목·이름을 만들지 않는다.
- 모든 슬롯을 한 번 이상 쓴다. 슬롯당 최대 두 종목, **세트가 5 이상일 때만** 두 종목(기구나 동작이 다른 것). 규칙 선택(7장)과 같은 상수다.
- 즐겨찾기한 종목은 특별한 이유가 없으면 고른다. 후보는 사용자에게 맞춘 순서이니 애매하면 앞쪽.
- 해 본 종목이 있는 슬롯에서는 해 본 종목을 먼저 고려하고, 그런 슬롯에서 처음 종목을 고르는 것은 루틴 전체 두 개까지. 해 본 종목이 없는 슬롯은 제한 밖이다.
- 순서: 큰 근육 종목을 앞에, 어깨·팔을 뒤에, 코어는 마지막. 한 슬롯의 두 종목은 이어서 두고 **여러 관절 종목을 고립 종목보다 앞에**.
- `comment`는 종목·순서를 고른 이유만 쓴다. 판정·세트 수·횟수·무게 등 **숫자를 쓰지 않는다.** 처방·단정 어투·의학적 표현 금지(실험 ①의 금지어 사전 재사용).
- 예시 한 개(few-shot). **예시가 행동을 크게 좌우한다** — r1 예시가 4세트를 두 종목으로 나눈 예였더니 첫날 루틴이 새 동작 여덟 개 × 2세트가 됐다.

### 5.3 모델과 호출

| 항목 | 값 | 근거 |
|---|---|---|
| 모델 | `gemini-3.5-flash-lite` | LLM 실험기록 9절 — 운영 모델 확정 |
| 출력 | `responseMimeType: application/json` + `responseSchema` | 형식 안정화(실험 7절) |
| `temperature` | 0.4 | 해설과 달리 매일 같은 조합만 나오지 않게 약간의 다양성. 실험에서 기록이 쌓인 케이스는 0.4에서도 매번 같은 조합(아래 11.5) |
| 타임아웃 | **10초** (처음 8초) | 실험 r2에서 같은 프롬프트의 지연이 회차에 따라 중앙값 1.5초 → 4.0초로 흔들렸고 8초에 2건 걸림. 관측 최대 7.0초 |
| 재요청 | 검증 실패(L1~L5) 시 **최대 2회** — 무엇이 틀렸는지 알려 준다 | 실험 8절 — N은 최소 2. 실험에서는 쓰일 일이 없었지만 비용이 없다 |
| 호출 실패 | 재요청하지 않고 **바로 규칙 선택**(`LLM_ERROR`) | 타임아웃·503을 다시 기다리게 하지 않는다 |
| 연동 구조 | 포트-어댑터: `LlmClient`(포트) + `GeminiClient`(어댑터) + `LlmRoutineComposer`(재요청·폴백) | 실험 2.2와 같은 구조. provider 교체 가능. 실험이 이 코드를 그대로 썼다 |
| 꺼짐 | `app.llm.enabled=false`(기본)면 LLM을 부르지 않고 규칙 선택(7장), `fallback_reason = LLM_DISABLED` | 개발·CI·장애 시. 운영은 서버 `.env`의 `LLM_ENABLED`·`GEMINI_API_KEY`로 켠다. 켰는데 키가 없으면 기동 실패 |
| 트랜잭션 | 판정·후보 읽기와 LLM 호출은 트랜잭션 밖, 저장만 한 트랜잭션 | LLM을 기다리는 동안 DB 연결을 붙잡지 않게 |

## 6. 검증

### 6.1 LLM 출력 검증 (재요청 대상)

| ID | 규칙 | 실패 예 |
|---|---|---|
| L1 | 스키마대로 파싱된다 | JSON 깨짐, 필드 누락 |
| L2 | 각 `exerciseId`가 **그 슬롯의 후보**다 | 등 슬롯에 가슴 종목 |
| L3 | 모든 슬롯이 1~2개 종목을 갖는다 | 삼두 슬롯이 빠짐 |
| L4 | 같은 종목이 두 번 나오지 않는다 | |
| L5 | 2개를 고른 슬롯은 세트가 5 이상이다 (규칙과 같은 상수) | 4세트 슬롯을 2+2로 쪼갬 |
| L6 | `comment`에 숫자·말로 쓴 수량("두 세트")이 없고, 처방 어미·의학 표현(부상·통증 등)이 없고, 120자 이하이며, "○○의 [고른 종목]"의 ○○가 부위 이름이다 | "가슴을 4세트…", "두 세트씩", "~하세요", "부상을 막으려고", "정의 랫풀다운"(등의) |

하나라도 실패하면 재요청한다. 2회 재요청 뒤에도 실패하면 **규칙 선택(7장)으로 대체**한다. `comment`만 실패하면(L6) 종목 선택은 받아들이고 설명을 규칙 문장(7.2)으로 바꾼다 — 선택이 멀쩡한데 문장 때문에 재요청하지 않는다.

### 6.2 최종 루틴 검증 (운동학적 기준)

LLM이든 규칙이든 **저장 직전의 최종 루틴**을 다음으로 검사한다. 기능명세서 2.3의 검사 항목을 정량화한 것이다.

| ID | 규칙 | 기능명세 2.3 |
|---|---|---|
| R1 | 부위별 계획 세트가 2~6이다 | 세트 수 권고 범위 |
| R2 | **이 루틴을 하면 부위의 주당 평균이 과다(20 초과)가 되지 않는다** — `주당 평균 + 오늘 세트 ≤ 20` | 세트 수 권고 범위 |
| R3 | 밀기/당기기·상체/하체가 이미 불균형이면, 루틴의 적은 쪽 세트 ≥ 많은 쪽 세트다 (불균형을 키우지 않는다) | 치우침 |
| R4 | 루틴의 모든 종목이 후보 목록 안이고, 세트가 규칙이 정한 값과 같다 | 후보·세트 준수 |
| R5 | 하루 총량이 상한(18) 이하다 | — |

규칙이 정한 세트를 서버가 채우므로 R1·R4·R5는 구성상 통과하고, R2·R3는 2~3장의 규칙이 지키도록 되어 있다. 그래도 매번 검사해 **통과율을 기록**한다 — 규칙의 구멍(예: 균형 보정이 판정 순서에 막혀 R3을 못 지키는 경우)이 있으면 실사용 데이터에서 드러난다. 실패한 루틴도 사용자에게는 주되, 실패 사유를 함께 저장해 11장에서 분석한다.

## 7. 규칙 선택 (폴백)

LLM이 꺼져 있거나, 호출이 실패하거나, 검증이 3번(최초 + 재요청 2회) 실패하면 규칙이 종목을 고른다. **항상 성공하고 검증이 필요 없다.**

### 7.1 선택

- 슬롯마다 **후보 1순위**(4.1 순서 — 즐겨찾기 → 자주 한 종목 → 새 종목)를 고른다.
- 슬롯 세트가 5 이상이고 계열이 다른 2순위 후보가 있으면 둘로 나눈다.
- 순서는 2.3의 크기 순(큰 근육 → 작은 근육, 코어 마지막).

### 7.2 설명 문장

그날 실제로 담긴 부위(큰 근육 = 가슴·등·앞허벅지·뒤허벅지/둔근, 작은 근육 = 어깨·팔, 코어)로 문장을 고른다. 고정 문장 하나를 쓰면 코어가 없는 날에도 "코어로 마무리"라고 말하게 된다.

| 담긴 부위 | 문장 |
|---|---|
| 큰 + 작은 + 코어 | 큰 근육부터 시작해서 작은 근육과 코어로 마무리하는 순서예요. |
| 큰 + 작은 | 큰 근육부터 시작해서 작은 근육으로 마무리하는 순서예요. |
| 큰 + 코어 | 큰 근육부터 시작해서 코어로 마무리하는 순서예요. |
| 작은 + 코어 | 작은 근육부터 하고 코어로 마무리하는 순서예요. |
| 큰 근육만 | 큰 근육 위주로, 큰 부위부터 하는 순서예요. |
| 작은 근육만 | 작은 근육 위주로 짠 날이에요. |
| 코어만 | 코어를 채우는 날이에요. |
| 담긴 부위 없음 | 최근에 운동한 부위가 회복 중이라 오늘은 쉬어 가도 좋아요. |

LLM의 `comment`가 L6에서 걸렸을 때도 이 표를 쓴다. 다만 그때는 순서가 LLM의 것이라, 큰 근육 → 작은 근육 → 코어 순서가 아니면 순서를 말하지 않는 **"요즘 덜 한 부위를 채우는 구성이에요."**를 쓴다.

## 8. 후보정

**하루에 루틴은 하나다.** "다시 만들기"는 두지 않는다 — 마음에 안 들면 후보정한다.

| 조정 | 방법 | 기록 |
|---|---|---|
| **종목 교체** | 같은 판정 부위에서, **기구가 다른 종목을 먼저** 보여 준다(LOG-08). 그다음 같은 기구. 해 본 종목이 앞 | 원래 종목을 `original_exercise_id`로 남김 |
| **세트 조정** | 1~10세트 | 원래 세트를 `original_sets`로 남김 |
| **종목 빼기** | 항목을 제외 | 지우지 않고 `removed`로 표시 |
| 다른 부위 하기 | 기록 화면에서 종목을 직접 추가 (지금처럼) | 루틴 밖 기록 → 수행률에 드러남 |

> **다시 만들기를 두지 않은 이유**: 후보정으로 거의 모든 불만을 풀 수 있고(종목·양·빼기), 하루 루틴이 하나여야 만족도·수행률이 루틴과 1:1로 대응한다. "몇 번 만에 받아들였나" 대신 **후보정 비율**이 추천이 맞았는지를 더 직접 보여 준다. LLM 호출도 하루 1회로 묶인다. (사용자 검토에서 정함 — LOG-40)

후보정 결과는 그날 루틴에 바로 저장되고, 원래 계획은 `original_*`로 남긴다. 수행률의 분모는 **후보정 전 원래 계획**이다(11.2).

| 측정 유형 | 표시 |
|---|---|
| 중량 × 횟수 | 8~12회 |
| 중량 추가 맨몸 | 8~12회 |
| 맨몸 × 횟수 | 10~15회 |
| 시간 | 30~60초 |

8~12회는 볼륨 권고가 세는 세트의 일반적인 범위다. 맨몸은 부하가 낮아 범위를 올렸다. **중량은 정하지 않는다** — 해 본 종목은 기록 화면이 지난 기록으로 채우고, 처음인 종목은 지금처럼 빈 칸으로 시작한다.

### 9.2 "이 루틴으로 기록"

루틴 계획은 서버(`routine_items`)에 있다. 기록 화면은 **열 때마다** 다음 둘을 합쳐 카드를 만든다.

1. 오늘 실제로 체크한 세트 (지금과 같음)
2. 오늘 루틴에서 아직 덜 한 부분 — 항목마다 `계획 세트 − 그 종목의 오늘 체크한 세트` 만큼 계획 줄

그래서 뒤로 갔다 오거나 앱을 껐다 켜도 루틴 카드가 그대로 나온다. 계획은 `routine_items`, 기록은 `workout_sets`라 **계획이 분석에 섞이지 않는다**(LOG-05 유지).

| 상황 | 결과 |
|---|---|
| 루틴 종목의 계획 줄에서 중량을 고치고 체크 전에 나감 | 브라우저 임시 저장으로 복원 (그날만) |
| 루틴 밖 종목을 추가하고 체크 전에 나감 | 브라우저 임시 저장으로 복원 (그날만) |

> **계획 줄을 서버에 저장하지 않은 이유**: `workout_sets`에 계획/완료 상태를 두는 방법도 검토했다. 세트를 읽는 집계 코드 약 15곳에 "완료만" 조건을 붙여야 하고, 하나라도 빠지면 하지 않은 운동이 볼륨에 섞여 **부족한 부위를 충분하다고 판정**한다 — LOG-05가 막은 오류다. 2~3일이 더 들어 루틴 배포가 늦어지는 것에 비해, 이득(다른 기기에서 이어 하기)이 작다. **향후 과제**로 둔다(LOG-40).

### 9.3 기록과 루틴의 연결

루틴을 만들 때 그날 기록(`workout_sessions`, 하루 하나)을 열어 `routine_id`를 채운다. 세션 생성 시 비워 두었던 컬럼(명세 6.2)에 이제 FK를 건다. 루틴과 기록이 날짜로 1:1이라 수행률은 "그날 기록의 부위별 세트 ↔ 그날 루틴의 부위별 계획"으로 계산한다(11.2).

## 11. 측정 — 검증 지표

기능명세서 5장 검증 계획의 지표를 다음으로 정의한다. **수집 도중 정의를 바꾸지 않는다.**

지표는 핵심 넷만 고정한다. 나머지는 **계산에 필요한 원본을 저장해 두고**(원래 계획 `original_*`, 후보정 내역, `first_time`, 체크한 세트) 결과를 해석할 때 필요하면 계산한다.

### 11.1 핵심 지표

| 지표 | 근거 | 정의 |
|---|---|---|
| **부위 수행률** | 계획서 7장, 기능명세 5장 | 아래 11.2 |
| **만족도** | 계획서 7장, 기능명세 5장 | 좋음·보통·별로 분포. 생성 방식(LLM/규칙)별로도 본다 |
| **운동학적 기준 통과율** | 기능명세 2.3 | 최종 루틴이 6.2(R1~R5)를 통과한 비율 |
| **LLM 1차 통과율** | 기능명세 2.3 | LLM 첫 응답이 6.1(L1~L6)을 통과한 비율 |

### 11.2 부위 수행률

```
            Σ 부위마다 min( 그날 그 부위의 체크한 본세트 , 루틴이 그 부위에 정한 원래 세트 )
수행률 = ─────────────────────────────────────────────────────────────────────
                         Σ 루틴이 정한 원래 세트 (후보정 전)

대상: 루틴을 받은 날 중 운동한 날(세트가 하나라도 있는 날)
```

| 정의의 선택 | 이유 |
|---|---|
| **종목이 아니라 부위 기준** | 루틴이 벤치프레스인데 덤벨 프레스로 가슴 4세트를 했다면 추천을 따른 것이다. 이 작품의 추천은 부족한 부위의 볼륨을 채우는 것이 목적이다 |
| **분모는 후보정 전 원래 계획** | 후보정 후 계획을 분모로 두면 4개 중 3개를 빼고 1개만 해도 100%가 된다. "추천한 양을 얼마나 했나"를 재려면 원래 계획이 기준이어야 한다. 줄이거나 뺀 만큼은 수행률이 낮게 나오고, 그 이유는 후보정 내역으로 해석한다 |
| **min으로 자름** | 계획보다 더 한 세트는 넘친 만큼 다른 부위의 미수행을 가리지 않게 |
| **운동한 날만** | 루틴을 보고 그날 운동을 못 한 것은 "루틴을 안 따랐다"가 아니라 "운동을 안 했다"다. 섞으면 수행률이 낮을 때 원인을 알 수 없다. 이런 날은 참고 지표(미수행률)로 따로 센다 |
| 본세트만 | 분석 판정과 같은 단위(워밍업 제외) |

**예시** — 루틴: 가슴 4 · 삼두 4 · 어깨 후면 4 (12세트)

| 실제로 한 것 | 수행률 |
|---|---|
| 루틴대로 전부 | 100% |
| 벤치프레스 대신 덤벨 프레스 4세트, 나머지는 루틴대로 | 100% |
| 어깨 후면을 빼고 나머지만 | 67% |
| 가슴 6세트 · 삼두 2세트 · 어깨 후면 0 | (4 + 2 + 0) ÷ 12 = 50% |
| 루틴만 받고 운동 안 함 | 대상 아님 (미수행 1일) |

### 11.3 참고 지표 (원본만 저장, 필요할 때 계산)

| 지표 | 원본 |
|---|---|
| 후보정 비율 | `original_exercise_id` · `original_sets` · `removed` |
| 종목 일치율 (추천 종목을 그대로 했나) | 루틴 항목 종목 ↔ 그날 체크한 세트의 종목 |
| 새 종목 수행률 / 익숙한 종목 수행률 | `first_time` |
| 미수행률 (루틴을 받고 운동 안 한 날) | `routines` ↔ 그날 기록 |
| 추천 이용률 (운동한 날 중 루틴을 받은 날) | `routines` ↔ 기록 |
| LLM 최종 채택률 · 폴백률(사유별) | `generated_by` · `fallback_reason` |

### 11.4 만족도를 묻는 시점

루틴 세트를 하나라도 체크한 날만 묻는다(안 한 루틴의 만족도는 의미가 없다). 그날 홈의 루틴 카드 아래 "오늘 루틴 어땠어요?"로 먼저 묻고, 답하지 않았으면 다음 홈 진입 때 한 번만 시트로 묻는다. 건너뛰면 다시 묻지 않는다. 좋음 / 보통 / 별로 한 번 누르면 끝나고, 보통·별로면 이유 하나를 고를 수 있다(종목이 안 맞음 / 양이 많음 / 양이 적음 / 기타).

### 11.5 오프라인 실험 (2026-10-24 완료)

LLM 실험 ①과 같은 하네스로, 합성 기록 케이스를 만들어 LLM 조합을 반복 실행한다.

| 케이스 예 | 보는 것 |
|---|---|
| 기록 없음 | 2.6의 첫날 루틴 |
| 밀기 편중 (가슴·삼두만) | 균형 보정, R3 |
| 하체 미수행 | 하체 우선 |
| 어깨 후면 0 (후보 3개) | 후보가 적은 슬롯 |
| 주 2회 / 주 5회 | 3.1 세트 분배 |
| 어제 가슴·등 | 회복 제외 |
| 즐겨찾기 다수 | 후보 순서 |

케이스당 10회 실행해 L1~L6 통과율, 재요청 횟수, 지연, `comment` 품질을 기록한다. 이 결과로 프롬프트·`temperature`·후보 수를 조정하고, 논문의 실험 장 자료로 쓴다.

**결과 (2026-10-24, 프롬프트 r1·r2 각 80회 — 상세는 LLM 실험기록 11절)**

| | r1 | r2 (채택) |
|---|---|---|
| 1차 통과 L1~L5 (응답 기준) | 80/80 | 77/77 |
| 설명 채택 L6 | 80/80 | 77/77 |
| 재요청 · 검증 실패 폴백 | 0 · 0 | 0 · 0 |
| 호출 실패 폴백 | 0 | 3 (타임아웃 2, 503 1) |
| R1~R5 실패 | 0 | 0 |
| 첫날 루틴(01) | 8종목 × 2세트 (9/10) | 4종목 × 4세트 (10/10) |
| 지연 중앙값 / 최대 | 1.5초 / 5.6초 | 4.0초 / 7.0초 |

통제는 두 회차 모두 위반 0이었고, r1→r2는 **루틴의 질**(쪼개기·슬롯 안 순서)을 고친 것이다. 실험 하네스는 `./gradlew llmExperiment`(운영 부품을 그대로 씀).

## 15. 구현 순서

검증 참여자가 루틴을 빨리 써야 수행률·만족도가 쌓이므로, **LLM 없이 완전히 동작하는 규칙 루틴을 먼저** 내보낸다.

| 단계 | 내용 | 배포 후 바로 쌓이는 지표 |
|---|---|---|
| 1 | V10 · 규칙 루틴(2~4장, 6.2, 7장) · API · 홈 카드 · 루틴 화면 · 후보정 · 기록 화면 연결 · 만족도 | 부위 수행률, 만족도, 운동학적 기준 통과율 |
| 2 | 오프라인 실험(11.5) — 프롬프트·수치 조정 | LLM 1차 통과율 (실험) |
| 3 | LLM 연결(5장, 6.1) | LLM 채택률, 폴백률, 생성 방식별 만족도 |

1단계의 규칙 선택은 3단계 이후에도 폴백으로 그대로 쓰여 버려지는 작업이 없다. 1단계와 3단계 사이에 쌓인 루틴은 `generated_by = RULE, fallback_reason = LLM_DISABLED`로 구분되어, **규칙 루틴과 LLM 루틴의 만족도·수행률 비교**가 자연스럽게 생긴다.

## 16. 결정 요약

| 항목 | 결정 |
|---|---|
| LLM 역할 | 종목 선택 · 순서 · 조합 설명만. **숫자 출력 없음** |
| 부위 선택 | 부족 → 권장 이하, 과다 제외, 48시간 회복 제외, 모자란 양 → 오래 쉰 순 → 큰 근육 순, 불균형은 같은 판정 안에서 적은 쪽 먼저 |

## 17. 한계 인지

- **회복 48시간은 근육 크기·강도를 구분하지 않는다.** 코어처럼 회복이 빠른 부위도 똑같이 뺀다. 실사용에서 코어가 너무 자주 빠지면 부위별 회복 시간을 둔다.
- **"큰 근육 → 작은 근육" 순서는 종목 단위의 복합/고립 구분이 아니다.** 종목 데이터에 복합 운동 표시가 없어서, 규칙 선택(7장)은 부위 순서로만 정하고 LLM에 종목 순서를 맡긴다. 규칙 루틴에서 고립 종목이 앞에 오는 경우가 있을 수 있다.
- **기구 제약을 미리 묻지 않는다.** 집에서 운동하는 사람에게 머신 종목이 나오면 후보정으로 바꿔야 한다. 후보정 비율이 높고 이유가 "종목이 안 맞음"이면 보유 기구 설정을 검토한다.
- **루틴은 하루 단위라 주간 계획이 아니다.** 주 3회 운동하는 사람에게 이번 주 남은 날을 고려한 배분은 하지 않는다. 대신 회복 제외와 오래 쉰 순 정렬이 날마다 다음 차례를 고르게 해, 결과적으로 분할에 가까워진다.
- **LLM 입력에 사용자의 분석 결과가 들어간다.** 개인을 식별하는 정보(이름·이메일)는 넣지 않지만, 무료 티어는 입력이 학습에 쓰일 수 있다(LLM 실험기록 10절). 개인정보처리방침에 "루틴 구성을 위해 부위별 운동량을 외부 AI 서비스에 보낸다"를 추가하고, 검증 참여자에게 알린다.
- **실험 케이스는 합성 기록이다.** 실제 사용자의 기록 분포에서 통과율이 다를 수 있어, 운영에서도 6.1·6.2 검증과 폴백을 상시 켠다.
