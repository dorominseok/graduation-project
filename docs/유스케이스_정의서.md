# 유스케이스 정의서
### 운동 습관 분석 기반 맞춤 루틴 추천 헬스 웹앱(PWA)

> 졸업작품 계획서 3장(시스템 요구사항)용 문서
> 우선순위: **기본 기능** / **핵심 기능** / **추가 기능**

---

## 1. 액터(Actor) 정의

| 액터 | 구분 | 설명 |
|---|---|---|
| **사용자** | 주 액터 | 운동을 기록하고 분석 결과와 추천 루틴을 받으며, 그룹에 참여하는 이용자. 그룹을 생성한 사용자도 동일 액터로 본다 |
| **LLM API** | 부 액터 (외부) | 선정된 후보 운동을 바탕으로 루틴을 구성하는 외부 서비스 |
| **FCM** | 부 액터 (외부) | 푸시 알림 발송을 담당하는 외부 서비스 (추가 기능) |

> 분석 모듈·추천 엔진·스케줄러는 시스템 내부 구성 요소이므로 액터로 두지 않으며, 시스템이 자동으로 수행하는 흐름으로 표기한다.

## 3. 주요 유스케이스 상세 명세

### UC-02-01 운동 세션 기록 ⭐

| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-02-01 |
| **명칭** | 운동 세션 기록 |
| **액터** | 사용자 |
| **개요** | 운동을 수행하며 종목별 세트를 기록한다. 분석·추천의 원천 데이터를 생성하는 유스케이스이다 |
| **사전 조건** | 로그인 상태 |
| **사후 조건** | 완료된 세션과 세트 기록이 저장되고, 운동 시간이 산출되며, 뱃지 판정(UC-04-01)이 수행됨 |

**기본 흐름**
1. 사용자가 운동 기록을 시작한다 (홈 화면 또는 추천 루틴 화면에서 진입)
2. 시스템이 진행 중인 세션을 생성한다
3. 사용자가 운동 종목을 선택한다
4. 시스템이 해당 종목의 직전 수행 기록을 세트 행에 자동으로 채운다
5. 사용자가 중량·횟수를 확인·수정하고 완료 체크한다
6. 시스템이 체크된 세트를 저장하고 저장 시각을 함께 기록한다
7. 3~6을 반복한다
8. 사용자가 운동 종료를 선택한다
9. 시스템이 세션을 완료 처리하고, 세트 저장 시각으로부터 총 운동 시간을 산출한다
10. 시스템이 뱃지 달성 여부를 판정한다 (UC-04-01)

**대체 흐름**
- 1a. 추천 루틴에서 진입한 경우 → 루틴의 종목과 세트 수만큼 행이 미리 표시된다. 표시된 행은 계획이며, 완료 체크한 세트만 저장된다
- 5a. 워밍업 세트인 경우 → 사용자가 워밍업으로 표시하며, 해당 세트는 볼륨 집계에서 제외된다
- 5b. 맨몸운동·시간 기반 종목인 경우 → 종목의 측정 유형에 따라 입력 항목이 달라진다

**예외 흐름**
- 8a. 사용자가 종료하지 않고 앱을 벗어난 경우 → 세션이 진행 중 상태로 유지되며, 재진입 시 "이어서 기록 / 종료"를 선택하게 한다
- 8b. 진행 중 상태로 자정이 지난 경우 → 마지막 세트 시각을 기준으로 자동 완료 처리한다
- 6a. 저장 실패(네트워크) → 입력값을 화면에 유지하고 재시도를 안내한다

### UC-02-06 과거 운동 기록 사후 입력

| 항목 | 내용 |
|---|---|
| **액터** | 사용자 |
| **개요** | 기록하지 못한 과거 운동을 날짜를 지정해 입력한다 |
| **사전 조건** | 로그인 상태 |
| **사후 조건** | 지정한 날짜의 세션으로 저장되어 볼륨 집계에 반영됨 |

**기본 흐름**
1. 사용자가 캘린더에서 날짜를 선택하고 기록 추가를 선택한다
2. 시스템이 해당 날짜의 사후 입력 세션을 생성한다
3. 사용자가 종목과 세트를 입력한다 (UC-02-01의 3~7과 동일)
4. 시스템이 세션을 저장한다

> 사후 입력 세션은 저장 시각이 실제 운동 시각과 다르므로 운동 시간을 자동 산출하지 않으며, 그룹 활동 공유의 총 운동 시간 집계에서 제외한다. 볼륨 집계에는 정상적으로 포함한다.
>
> 기록 누락은 분석에서 "볼륨 부족"으로 오판되므로, 사후 입력을 허용하는 것이 데이터 품질에 유리하다.

### UC-03-03 오늘의 루틴 추천 요청 ⭐

| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-03-03 |
| **명칭** | 오늘의 루틴 추천 요청 |
| **액터** | 사용자(주), LLM API(부) |
| **개요** | 운동하려는 시점에 그때까지 쌓인 기록을 분석해, 약점을 보완하는 오늘의 루틴을 생성한다 |
| **사전 조건** | 로그인 상태 / 최소 N회 이상의 운동 기록 존재 |
| **사후 조건** | 검증을 통과한 추천 루틴이 저장되고 사용자에게 표시됨 |

**기본 흐름**
1. 사용자가 "오늘 루틴 추천받기"를 선택한다
2. 시스템이 최근 4주 운동 기록을 부위별로 집계한다
3. 시스템이 기준(ACSM 가이드라인)과 비교해 부족·불균형 부위를 판별한다
4. 시스템이 보완 우선순위를 산출한다
5. 시스템이 운동 종목 DB에서 해당 부위의 운동 후보를 조회한다
6. 시스템이 분석 결과와 운동 후보를 LLM API에 전달해 루틴 구성을 요청한다
7. LLM API가 오늘의 루틴(운동·세트·횟수)을 반환한다
8. 시스템이 반환된 루틴을 정량 규칙으로 검증한다 (UC-03-04)
9. 검증을 통과하면 루틴을 저장하고 사용자에게 표시한다
10. 사용자는 필요에 따라 운동을 교체하거나 세트를 조정한다 (UC-03-05)

**대체 흐름**
- 3a. 부족·불균형이 없는 경우 → 현재 균형을 유지하는 루틴을 생성한다
- 8a. 검증 실패 시 → 최대 N회까지 재생성을 시도한다
- 8b. 재시도 후에도 실패 시 → 규칙 기반 기본 루틴을 대체 제공하고 사용자에게 안내한다

**예외 흐름**
- 2a. 운동 기록이 부족한 경우 → 추천 불가 안내 및 기록 유도 화면으로 이동
- 6a. LLM API 호출 실패(네트워크·한도 초과) → 규칙 기반 기본 루틴으로 대체하고 안내

### UC-03-01 운동 습관 약점·불균형 분석

| 항목 | 내용 |
|---|---|
| **액터** | 시스템 자동 |
| **개요** | 사용자의 운동 기록을 집계해 부위별 부족·과다와 밀기/당기기·상하체 불균형을 판별한다 |
| **사전 조건** | 분석 대상 기간(최근 4주)의 운동 기록 존재 |
| **사후 조건** | 부족·불균형 판정 결과가 산출되어 추천의 근거 및 조회 화면에 사용됨 |

**기본 흐름**
1. 최근 4주의 완료된 세션에서 본세트 기록을 조회한다 (진행 중 세션·워밍업 세트 제외)
2. 각 기록을 주동근 기준으로 부위별 분류한다 (가슴/등/하체/어깨/팔/코어)
3. 부위별 주간 평균 세트 수를 집계한다
4. 판정 기준에 따라 상태를 분류한다
   - 주 4세트 미만 → 부족
   - 주 4~10세트 → 권장 이하
   - 주 10~20세트 → 최적
   - 주 20세트 초과 → 과다
5. 밀기·당기기 및 상·하체 볼륨 비율을 계산해, 한쪽이 2배를 초과하면 불균형으로 판정한다
6. 판정 결과를 반환한다

### UC-03-05 추천 루틴 후보정

| 항목 | 내용 |
|---|---|
| **액터** | 사용자 |
| **개요** | 생성된 추천 루틴을 사용자가 자신의 상황에 맞게 조정한다 |
| **사전 조건** | 추천 루틴이 생성되어 표시된 상태 |
| **사후 조건** | 수정된 루틴이 저장되어 운동 수행의 기준으로 사용됨 |

**기본 흐름**
1. 사용자가 추천 루틴에서 조정할 항목을 선택한다
2. 운동을 교체하는 경우, 시스템이 **같은 부위이면서 기구가 다른 종목을 우선하여** 대체 후보를 제시한다
3. 사용자가 대체 운동을 선택하거나 세트·횟수를 조정한다
4. 시스템이 수정된 루틴을 저장한다

> 부상 부위나 보유 기구 등 개별 제약을 사전에 입력받지 않는 대신, 이 후보정 과정을 통해 사용자가 직접 조정한다.

> **2단계 보충**: 부위만으로 후보를 고르면 교체 사유(기구 사용 불가 등)를 해소하지 못하므로, `exercises.equipment`를 후보 선정에 사용한다. 상세 근거는 「설계 변경 로그」 LOG-08 참조. 후보 정렬 기준과 교체 트리거 방식은 10월 루틴 추천 설계에서 확정한다.

### UC-05-02 초대코드로 그룹 참여

| 항목 | 내용 |
|---|---|
| **액터** | 사용자 |
| **개요** | 전달받은 초대코드를 입력해 친구 그룹에 참여한다 |
| **사전 조건** | 로그인 상태 / 유효한 초대코드 보유 |
| **사후 조건** | 사용자가 해당 그룹의 멤버로 등록되고 활동 현황에 반영됨 |

**기본 흐름**
1. 사용자가 "그룹 참여"를 선택한다
2. 사용자가 초대코드를 입력한다
3. 시스템이 코드의 유효성을 검증한다
4. 시스템이 사용자를 그룹 멤버로 등록한다
5. 그룹 화면(활동 현황)으로 이동한다

**예외 흐름**
- 3a. 코드가 존재하지 않거나 만료된 경우 → 오류 메시지 표시
- 3b. 이미 해당 그룹의 멤버인 경우 → 안내 후 그룹 화면으로 이동

### UC-04-01 뱃지 달성 조건 판정 및 지급

| 항목 | 내용 |
|---|---|
| **액터** | 시스템 자동 |
| **개요** | 운동 기록 저장 시 뱃지 달성 여부를 판정하고 자동 지급한다 |
| **사전 조건** | 운동 기록이 저장됨 |
| **사후 조건** | 조건 충족 시 뱃지가 지급되고 사용자에게 표시됨 |

**기본 흐름**
1. 운동 기록 저장 이벤트가 발생한다
2. 시스템이 미획득 뱃지의 달성 조건을 조회한다
3. 사용자 누적 기록과 조건을 비교한다 (예: 3대 500, 스쿼트 100회 등)
4. 조건을 충족한 뱃지를 지급하고 획득 이력에 저장한다
5. 사용자에게 뱃지 획득을 표시한다

## 4. 유스케이스 다이어그램 (구성 안내)

액터는 **사용자**(주), **LLM API**·**FCM**(외부)으로 구성한다.

```
              ┌──────────── 시스템 경계 ────────────┐
              │                                    │
              │  (회원가입)  (로그인)  (프로필 설정) │
              │                                    │
              │  (운동 세션 기록)  (히스토리 조회)   │
              │  (기록 수정/삭제)  (사후 입력)       │
              │  (통계 조회)  (운동 종목 검색)       │
              │                                    │
사용자 ───────┤  (오늘의 루틴 추천 요청)            │─────── LLM API
              │        ↑ include                   │
              │   (약점·불균형 분석)                │
              │        ↑ include                   │
              │   (추천 루틴 품질 검증)             │
              │                                    │
              │  (루틴 후보정)  (피드백 제출)        │
              │  (약점 분석 결과 조회)              │
              │                                    │
              │  (뱃지 조회)  (뱃지 목표 확인)       │
              │                                    │
              │  (그룹 생성)  (그룹 참여)            │
              │  (그룹 활동 현황 조회)  (그룹 탈퇴)  │
              │                                    │
              │  (알림 설정)                        │
              │  (알림 발송) ······················ │─────── FCM
              │                                    │
              └────────────────────────────────────┘
```

**관계 표기**
- `오늘의 루틴 추천 요청` → `약점·불균형 분석` : **include** (항상 수행)
- `오늘의 루틴 추천 요청` → `추천 루틴 품질 검증` : **include** (항상 수행)
- `알림 발송` → `약점 부위 보완 제안 알림` : **extend** (조건부)
- 알림 관련 유스케이스는 추가 기능이므로 점선 등으로 구분 표기

> 작도 도구: draw.io, StarUML 중 택1
