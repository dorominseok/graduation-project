# 기록 가져오기 설계서

> 2026-11-19 작성. 다른 앱 기록 붙여넣기 — 친구들 사용 후기에서 나온 요청 4번.
> 화면은 로컬 시안으로 사용자와 정했다(브랜치 `proto/import`, 올리지 않음). 우리 DB에 없는 운동은 내 종목(「내종목_설계서」, #62·#63)의 만들기 창을 미리보기에서 열어 만든다.
> 다른 세션이 이어 받을 때 이 문서만 읽고 시작할 수 있게 결정·규칙·완료 기준을 모두 적는다.
> 2026-11-19 서버 구현(PR 1)에서 다듬은 것: 결정 7의 고정 번호(같은 이름의 몇 번째), 4장의 2번 조건·4번 비김·기록 방식, 6장의 저장 시각, 7장 응답의 `allowedMeasureTypes`.
> 2026-11-20 화면 구현(PR 2)에서 정한 것: 5장의 고른 종목은 같은 원래 이름 모두에, 바꾸기 시트·만들기 창은 담을 수 있는 기록 방식만, 다시 넣었을 때·읽을 것이 없을 때·형식이 아닐 때의 문구.

---

## 1. 무엇을 하나

- 다른 운동 기록 앱(첫 판은 **바디캘린더**)의 "운동 일지 내보내기" 글을 붙여넣으면, 날짜별로 읽어 우리 종목에 맞춘 미리보기를 보여 주고 "추가"로 그날 기록에 넣는다.
- 지난 기록을 옮기는 것이 주된 쓰임이다 — 여러 날을 한 번에 붙여넣을 수 있다.
- 들어간 기록은 직접 기록한 것과 똑같이 분석·회복·1RM에 들어간다.

## 2. 결정

| # | 결정 | 이유 |
|---|---|---|
| 1 | 첫 판은 바디캘린더 형식만 읽는다 | 받은 샘플이 이 앱뿐이다. 다른 앱은 샘플이 생기면 읽는 규칙을 더한다 |
| 2 | 읽기·이름 맞추기는 **서버**가 한다 | 규칙을 테스트로 고정할 수 있고, 맞춘 이름 기억(결정 9)과 내 종목을 서버가 안다 |
| 3 | **유산소는 뺀다.** 미리보기에 그 줄도 두지 않는다 | 근력 분석 앱이라 속도·구간을 담을 칸이 없고, 내 종목도 부위가 있어야 만든다. 붙여넣기 화면 아래 "유산소는 기록하지 않아요" 한 줄로 알린다(사용자 의견 — 미리보기에는 추가할 종목만) |
| 4 | `웜업` → 워밍업 세트, `드랍` → 본세트 | 워밍업은 분석에서 빠지는 것이 맞고, 드랍세트는 실제 운동량이다. 우리 앱에 드랍 표시는 없다 |
| 5 | 요약 줄의 `N분`을 그날 운동 시간으로 — **그날 기록이 비어 있었을 때만** | 가져온 세트는 한꺼번에 저장돼 우리 계산으로는 1분 남짓이 된다. 이미 기록이 있는 날은 그 시간을 덮지 않는다. `N분`이 없으면 비운다 |
| 6 | 그날 기록이 이미 있으면 **아무 말 없이** 그 뒤에 이어 붙인다 | 사용자 의견 — 안내를 붙이면 오히려 헷갈린다 |
| 7 | **같은 글을 두 번 넣어도 한 번만** 들어간다 | 세트마다 고정 번호(`clientSetId`)를 만든다 — 사용자·날짜·원래 이름·그 이름이 그날 몇 번째로 나왔는지·몇 번째 세트로 정해지는 UUID(v5). 세트 저장의 멱등(명세 6.4)이 두 번째를 건너뛴다. "몇 번째 종목"으로 하면 화면에서 다른 종목을 빼고 넣었을 때 번호가 밀린다 |
| 8 | 여러 날을 한 번에 — 날짜 줄마다 나눈다. 한 번에 31일까지 | 지난 기록을 하루씩 옮기면 번거롭다. 한 달 치면 미리보기가 감당할 길이다 |
| 9 | **맞춘 이름을 기억한다**(V17) — "바꾸기"로 고르거나 미등록 운동을 만들면 그 짝을 계정에 저장 | 같은 사람이 같은 이름을 다시 붙여넣을 때 손댈 일이 없게. "비슷한 종목"을 그대로 둔 것은 저장하지 않는다 — 다음에도 같은 규칙으로 같은 답이 나온다 |
| 10 | "비슷한 종목"은 추가를 막지 않는다. **미등록 운동만 막는다** | 비슷한 종목은 대개 맞고, 틀리면 바꾸기로 고친다. 미등록은 넣을 종목이 없다 |
| 11 | 문구: 없는 종목은 **"미등록 운동"**. 요약 칸은 첫 줄과 미등록 안내만, 다 맞췄을 때는 문장 없음 | 사용자 의견 — "우리 앱에 없는 종목"은 어색하고, 다 맞췄다는 건 초록으로 바뀌는 "추가" 버튼이 말한다 |
| 12 | 미래 날짜의 일지는 읽지 않는다(미리보기·수에서 빠진다) | 세트 저장이 미래 날짜를 받지 않는다. 드물어서 따로 알리지 않는다 |

## 3. 글 읽는 규칙

빈 줄로 나뉜 덩어리를 차례로 읽는다. 받은 샘플 두 개(2026-11-17 "488번째", 2026-11-18 "472번째")가 기준이다.

| 줄 | 예 | 규칙 | 처리 |
|---|---|---|---|
| 날짜 | `2026-11-18 바디캘린더 472번째 운동 일지` | `^(\d{4}-\d{2}-\d{2}) 바디캘린더` | 새 날 시작 |
| 부위 요약 | `유산소1 복부1 등1 가슴1` | 날짜 줄 다음, "낱말+숫자"만 있는 줄 | 버림 |
| 전체 요약 | `자유 운동 3분 10세트 2.8톤` | `^자유 운동 (\d+)분` | `N분` → 결정 5. 나머지는 버림 |
| 종목 이름 | `풀업: 중량`, `(슈퍼세트) 푸시다운` | 세트 줄이 아닌 덩어리 첫 줄 | `(슈퍼세트)`를 떼고 `:` 앞이 이름, 뒤가 수식어(쉼표로 여러 개) |
| 무게·횟수 | `1세트 40kg 10회` | `^\d+세트 ([\d.]+)kg (\d+)회$` | 무게 × 횟수 |
| 횟수만 | `1세트 30회` | `^\d+세트 (\d+)회$` | 횟수 |
| 시간 | `1세트 02:00` | `^\d+세트 (\d{1,2}):(\d{2})$` | 시간(초) |
| 웜업·드랍 | `웜업 20kg 10회`, `드랍 40kg 10회` | `^(웜업\|드랍) …` 위와 같은 꼴 | 결정 4 |
| 유산소 | `1구간 9.0km/h 04:30 1` | `^\d+구간 ` | 그 종목을 통째로 뺀다(결정 3) |
| 그 밖의 줄 | | | 건너뛰고 서버 로그에 개수와 앞의 세 줄을 남긴다 — 바디캘린더 형식이 바뀌면 알아채게. 세트 줄이 없는 이름 줄도 여기 |

- 줄 앞뒤 공백·여러 칸·줄바꿈 없는 공백(U+00A0)·CRLF는 정리하고 읽는다. 빈 줄이 빠져도 세트 줄 다음의 이름 줄이 새 종목을 연다. 같은 날짜가 두 번 나오면 한 날로 합친다.
- 날짜 줄이 하나도 없으면 `400 IMPORT_FORMAT_UNKNOWN`("바디캘린더 운동 일지 형식이 아니에요"). 글은 100KB까지, 날은 31일까지(`400`).
- 맨몸 종목의 kg(예: `풀업: 맨몸 81kg`)은 체중이라 버린다. 일반 규칙은 **맞춘 종목의 기록 방식이 쓰지 않는 값은 버린다** — 세트 저장(6.4)과 같다.

## 4. 이름 맞추기

이름·수식어를 아래 순서로 맞춰 본다. 앞에서 맞으면 거기서 끝난다. 후보는 **그 사용자에게 보이는 종목**(기본 종목 + 숨기지 않은 내 종목)이다.

| 순서 | 방법 | 결과 |
|---|---|---|
| 1 | **내가 맞춘 짝**(V17) — 원래 이름 전체(`풀업: 중량`)가 같으면 | 맞춤 |
| 2 | **이름이 똑같음** — 원래 이름 전체가 기본 종목·내 종목 이름과 같으면(띄어쓰기·수식어 순서 무시, 내 종목 먼저). 수식어가 없거나 `기본`·`스탠딩`·`맨몸`뿐이면 `:` 앞 이름만으로도 | 맞춤 |
| 3 | **미리 만든 짝 표** — `backend/src/main/resources/data/import_bodycalendar.csv`(원래 이름 → 우리 이름) | 맞춤 |
| 4 | **계열 + 수식어** — `:` 앞 이름(띄어쓰기를 뺀 것)이 어떤 계열 이름으로 끝나면(여럿이면 긴 계열) 그 계열 안에서, 수식어 낱말이 이름에 가장 많이 들어 있는 종목. 비기면 `:` 앞 이름의 낱말이 많이 든 종목 → 흔한 종목(`common_rank`) → id 순 | **비슷한 종목** |
| 5 | 아무것도 안 맞음 | **미등록 운동** |

- **짝 표의 첫 내용**(샘플에 나온 것). 대상 이름은 모두 시드에 있다(테스트로 확인).

| 바디캘린더 | 우리 종목 |
|---|---|
| 풀업: 맨몸 | 풀업 |
| 풀업: 중량 | 중량 풀업 |
| 플랭크: 기본 | 플랭크 |
| 랫풀다운: 오버핸드 | 랫풀다운: 와이드 그립 |
| 랫풀다운: 언더핸드 | 랫풀다운: 언더그립 |
| 벤치 프레스: 바벨 | 바벨 벤치프레스 |
| 숄더 프레스: 스탠딩, 원암, 덤벨 | 원암 덤벨 숄더프레스 |
| 트라이셉스 익스텐션: 스탠딩, 덤벨 | 덤벨 오버헤드 익스텐션 |
| 푸시다운 | 케이블 푸시다운 |
| 페이스 풀: 케이블 | 페이스풀 |
| 사이드 레터럴 레이즈: 핀 머신 | 머신 레터럴 레이즈 |

- **2번의 `:` 앞 이름 맞추기를 수식어가 뜻 없는 말일 때만 하는 이유** — `덤벨 컬: 번갈아가며, 인클라인`을 "덤벨 컬"에 맞추면 인클라인이 사라진다. 이런 이름은 4번으로 보내 수식어까지 본다.
- **4번의 수식어 낱말**은 우리 표현으로 바꿔 비교한다: 언더핸드 → 언더그립, 번갈아가며 → 얼터네이트, 핀 머신 → 머신. 그 밖의 말(기구 이름, 스탠딩 등)은 그대로 — 어느 후보에도 없는 말은 모두에게 0이라 결과를 바꾸지 않고, 스탠딩은 `바벨 스탠딩 카프레이즈`처럼 우리 이름에도 있다.
  - 예: `덤벨 컬: 번갈아가며, 인클라인` → "덤벨컬"은 계열 "컬"로 끝난다 → 얼터네이트 덤벨 컬과 인클라인 덤벨 컬이 수식어 하나씩으로 비긴다(이름 낱말 "덤벨"·"컬"도 같다) → 흔한 쪽(인클라인 덤벨 컬) → "비슷한 종목".
  - 수식어를 이름 낱말보다 먼저 세는 이유 — `사이드 레터럴 레이즈: 핀 머신`을 이름 낱말까지 한데 세면 "덤벨 사이드 레터럴 레이즈"가 "머신 레터럴 레이즈"와 비긴다.
- **기록 방식이 맞는 종목만** 후보로 본다. 세트를 담을 수 있는 방식 = 그 방식이 꼭 받는 값이 모든 세트에 있는 것 — kg·회면 무게 × 횟수·맨몸 + 추가 무게·횟수만(kg는 버림), 회만 있으면 횟수만, 시간이면 시간. 미리보기 응답의 `allowedMeasureTypes`이고 "바꾸기" 목록도 이것이다.
  - 1\~3번은 근거가 분명해 담을 수만 있으면 된다. 짐작인 4번은 kg가 적힌 세트를 맨몸(횟수만) 종목으로 짐작하지 않는다 — 원래 이름에 "맨몸"이 있으면 본다.
- 내 종목도 2번(이름 똑같음)으로 맞는다 — 미리보기에서 만든 내 종목은 글의 이름 그대로라 다음엔 1·2번으로 바로 맞는다.

## 5. 화면

1. **기록 화면 머리줄 오른쪽 "⋮"** → "더 보기" 시트 → "다른 앱 기록 붙여넣기 — 바디캘린더에서 내보낸 운동 일지를 그대로 붙여넣어요".
2. **붙여넣기 화면**(`/session/import`): 안내 "바디캘린더의 운동 일지 내보내기 글을 그대로 붙여넣으세요. 여러 날을 이어 붙여도 날짜별로 나눠 읽어요." → 큰 입력칸 → "미리보기" → 아래 "유산소는 기록하지 않아요. 웜업은 워밍업 세트로, 드랍은 본세트로 넣어요."
   - 형식이 아니거나(`IMPORT_FORMAT_UNKNOWN`) 너무 길면 입력칸 아래에 빨간 글씨로 서버 문구("바디캘린더 운동 일지 형식이 아니에요.").
3. **미리보기**(그룹 멤버 하루 기록과 같은 카드). 머리줄 오른쪽 **"추가"**(미등록 운동이 남으면 회색).
   - 요약 칸: "바디캘린더 기록 2일 · 8종목 · 40세트를 읽었어요", 미등록이 있으면 빨간 "미등록 운동 1개를 만들거나 고르면 추가할 수 있어요". 다 맞으면 첫 줄만.
   - 날짜 줄: "11월 18일 (수) · 3분 · 12세트"(`N분`이 없으면 세트 수만). 그날 기존 기록은 보여 주지 않는다(결정 6).
   - 읽을 근력 기록이 없으면(유산소만, 미래 날짜만) 요약 칸에 "가져올 근력 운동 기록이 없어요 / 유산소와 오늘 이후 날짜의 일지는 가져오지 않아요", "추가"는 회색.
   - 종목 카드: 우리 종목 이름 + 회색 "바디캘린더 · 원래 이름" + 오른쪽 "바꾸기". 비슷한 종목이면 노란 "비슷한 종목", 미등록이면 빨간 "미등록 운동"과 "+ 새 종목 만들기"·"비슷한 종목 고르기". 아래는 세트 칸(워밍업은 "워밍업", 시간은 초, 추가 무게는 "+40kg"). 내 종목이면 파란 "내 종목".
   - "+ 새 종목 만들기": 내 종목 만들기 창이 이름(원래 이름 그대로)·기구·기록 방식(글에서 짐작)이 채워진 채 열린다 — 이름에 "케이블"이 있으면 케이블, "머신"이면 머신, 세트에 kg가 있으면 무게 × 횟수, 없거나 "맨몸"이면 횟수만. 버튼 "만들고 이 기록에 쓰기".
   - 만들기 창의 이름은 내 종목 상한 50자까지 채운다. 기록 방식은 그 세트를 담을 수 있는 것(`allowedMeasureTypes`)만 누를 수 있고("가져온 기록에 맞는 방식만 고를 수 있어요"), 기구를 바꿀 때의 기본 방식도 그 안에서 고른다.
   - "바꾸기"·"비슷한 종목 고르기": 종목 고르기 시트(기록 방식이 맞는 종목만 — 방식이 하나면 서버가 거르고, 여럿이면 받은 목록에서 거른다). 이 시트에는 만들기 버튼을 두지 않는다 — 미리 채우는 만들기가 카드에 따로 있다.
   - **고른 종목은 그 원래 이름 모두에** — 여러 날에 같은 이름이 나오면 한 번 고르거나 만들면 모든 날이 바뀐다. 서버가 기억하는 짝(결정 9)도 원래 이름 하나에 종목 하나다. 고르거나 만든 종목은 저장 때 `remember: true`.
4. **추가** → 저장 → 가져온 날 중 가장 최근 날의 기록 화면으로 바꿔 간다(뒤로 가면 원래 기록 화면). 알림 "N일 기록을 가져왔어요", 같은 글을 다시 넣어 새로 들어간 세트가 없으면 "이미 가져온 기록이에요".

## 6. 데이터 — `V17__exercise_import_aliases.sql`

```sql
-- 맞춘 이름 기억(결정 9). 사람마다 따로
CREATE TABLE exercise_import_aliases (
    id          BIGSERIAL PRIMARY KEY,
    user_id     BIGINT       NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    source_name VARCHAR(200) NOT NULL,   -- 바디캘린더의 원래 이름 전체(띄어쓰기 정리)
    exercise_id BIGINT       NOT NULL REFERENCES exercises(id) ON DELETE CASCADE,
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
    CONSTRAINT uq_import_alias UNIQUE (user_id, source_name)
);
```

- 짝의 종목이 숨겨졌거나 보이지 않으면 그 짝은 없는 것으로 본다(다음 순서로 맞춘다).
- 탈퇴: 연쇄 삭제. 내 종목을 지우면 그 짝도 연쇄 삭제.
- **가져온 세트의 기록 시각**(`recorded_at`)은 그날 정오(Asia/Seoul) + 세트 순서만큼 초 — 순서가 지켜지고, 오늘 진행 중인 기록이나 "자정 넘겨 이어지는 어제 기록" 판정(명세 6.2)에 끼지 않는다.
  - 오늘 정오 전에 오늘 일지를 가져오면 마지막 세트가 지금 1초 전에 오게 당긴다 — 앞으로의 시각이 기록되지 않게.
  - 그날 세트가 이미 있고 그 마지막이 이보다 늦으면 그 1초 뒤부터 — 결정 6의 "이어 붙인다"가 화면 순서로도 지켜진다.

## 7. API — 「API 명세서」에 13장 신설

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| POST | `/imports/preview` | 글을 읽어 날짜별 종목·세트와 맞춘 결과를 돌려준다. 저장하지 않는다 |
| POST | `/imports` | 미리보기에서 정한 대로 저장한다 |

**미리보기 요청·응답**

```json
// 요청
{ "text": "2026-11-18 바디캘린더 472번째 운동 일지\n…" }
// 응답 200
{ "days": [ { "date": "2026-11-18", "minutes": 3, "exercises": [
    { "source": "풀업: 중량", "status": "MATCHED",
      "exercise": { "id": 23, "nameKo": "중량 풀업", "measureType": "WEIGHTED_BODYWEIGHT", "mine": false },
      "guess": null, "allowedMeasureTypes": ["WEIGHT_REPS", "BODYWEIGHT_REPS", "WEIGHTED_BODYWEIGHT"],
      "sets": [ { "kind": "SET", "weightKg": 40, "reps": 10, "durationSec": null } ] },
    { "source": "월 슬라이드", "status": "UNREGISTERED", "exercise": null,
      "guess": { "equipment": "BODYWEIGHT", "measureType": "BODYWEIGHT_REPS" },
      "allowedMeasureTypes": ["BODYWEIGHT_REPS"],
      "sets": [ { "kind": "SET", "weightKg": null, "reps": 30, "durationSec": null } ] } ] } ] }
```

- `status`: `MATCHED`·`SIMILAR`·`UNREGISTERED`. `kind`: `SET`·`WARMUP`·`DROP`(저장은 본세트).
- 유산소·미래 날짜는 응답에 없다. `guess`는 미등록 운동일 때만.
- `sets`는 글에 적힌 그대로(맨몸 kg 포함) — 고른 종목이 쓰지 않는 값은 화면이 안 보이고 저장할 때 버린다. 바꾸기로 무게 종목을 고를 수도 있어서다.

**저장 요청·응답**

```json
// 요청 — 미등록 운동은 화면이 먼저 내 종목을 만들어 그 id를 넣는다
{ "days": [ { "date": "2026-11-18", "minutes": 3, "exercises": [
    { "source": "풀업: 중량", "exerciseId": 23, "remember": false, "sets": [ … ] } ] } ] }
// 응답 201
{ "days": [ { "date": "2026-11-18", "sessionId": 812, "added": 12, "alreadyThere": 0 } ] }
```

- `remember`: 화면이 "바꾸기"로 고쳤거나 미리보기에서 만든 종목이면 `true` → 그 짝을 저장(이미 있으면 바꿈).
- 서버가 다시 확인한다: 보이는 종목인지(아니면 `404`), 기록 방식에 맞는 값인지(맞지 않는 값은 버리고, 필요한 값이 없으면 `400`), 미래 날짜(`400`).
- 같은 글을 다시 넣으면 `added: 0, alreadyThere: N`(결정 7).
- 하루라도 막히면 아무것도 넣지 않는다(한 트랜잭션). 날짜가 겹치면 `400`.
- 운동 시간: 그날 기록에 세트가 하나도 없었고 `minutes`가 있으면 `durationOverrideSec = minutes × 60`(결정 5).
