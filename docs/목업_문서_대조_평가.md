## 총평

목업은 **기록 화면(세션·세트 입력)** 축에서는 문서와 꽤 잘 맞는다 — 세트 1행 저장, 완료 체크로 확정, 3단 프리필, 워밍업 토글과 "볼륨 집계에서 제외됨" 문구까지 「운동기록_방식_설계서」 3장을 정확히 반영하고 있다.

반면 **분석·통계 화면**은 문서가 8월에 확정한 규칙보다 앞선 세대의 설계에 머물러 있고, 가장 위험한 축이 여기다. 특히 「분석 로직 설계서」 2.4가 만든 핵심 규칙 — *판정은 하위 9종에, 상위 6종에는 판정 라벨을 붙이지 않는다* — 이 목업에는 전혀 반영돼 있지 않고 정반대(상위 6종에 판정 라벨 직접 부착)로 돼 있어, LOG-09가 지적한 "팔 12세트 · 최적" 오해를 그대로 재생산한다.

두 번째 위험 축은 **세션 생명주기**로, `DRAFT` 단일 제약·세트 0개 종료·세션 삭제 부재가 겹쳐 API를 그대로 붙이면 409/422가 사용자에게 그대로 노출된다.

세 번째는 **프론트가 판정·집계를 직접 계산**하는 구조 전반(집계 창, 운동 시간, 톤 볼륨, 강도 %)으로, 서버가 완성해서 내려준다는 LOG-10 원칙과 충돌한다.

덧붙여, `API_명세서.md` 9.2가 "어깨(앞)/어깨(뒤) 2계층 표시는 목업 그대로 유지된다"고 적은 것은 **사실과 다르다** — 목업에 그 표시는 존재하지 않는다.

## E. 부수 사항

### 목업 안의 지시문성 문장

없었다. 하단 "화면 흐름도 (문서용 참고)" 섹션(**1778–1819**)과 "참고: 상태 변형" 섹션(**1821–1911**)은 설계 참고용 서술이며 지시로 읽힐 문장은 없다. 다만 흐름도 **1810**의 "세션 상세(**수정·삭제**)"는 실제 화면에 삭제가 없어 **흐름도가 화면보다 앞서 있다**(C-20).

### Dead code — 구현 이관 시 따라오지 않게 주의

`recentRecords` / `weaknessSummary` / `isBalanced` / `bodyPartChips` / `singleChart` / `multiChart` / `multiLegend` / `trendStatsLine` / `toast`·`undoToast` / `onMoveUp`·`onMoveDown` / `longPressSetId` 계열이 `renderVals`에서 계산되지만 **템플릿에서 한 번도 참조되지 않는다.**

### 문서와 잘 맞는 부분 — 그대로 가져가도 되는 것

- 세트 1행 + 완료 체크 구조
- 3단 프리필(종목 프리필 **2499–2507**, 세트 복사 **2427–2432**, "이전 기록에서 채움" 배지 **584–586**)
- 워밍업 토글과 "볼륨 집계에서 제외됨" 문구
- ±2.5kg / ±1회 스테퍼
- 즐겨찾기 별표
- 재진입 다이얼로그의 "이어서 기록 / 세션 종료" 2지선다(기록 방식 5.1)
- `DONE` 세션 사후 편집 허용
- 대체 후보 시트의 "같은 부위 · 다른 기구" 문구(기능명세 2.4)
- 그룹 탭의 "준비 중" 처리
