## D-01. 회복 상태는 날짜·세트 수로, 그림은 2D 앞·뒤 두 장 (2026-11-10)

- 상황: 분석 탭의 통계 서브탭 자리에 부위별 회복 상태를 인체 그림으로 보여 주기로 했다. 무엇으로 피로를 짐작하고 어떤 그림을 쓸지 정해야 했다.
- 안
  - 기준: A. 무게×횟수(볼륨) / **B. 운동한 날짜 + 세트 수 ← 선택**
  - 그림: **A. 2D 앞·뒤 두 장 ← 선택** / B. 3D 돌려 보기
- 고른 이유: 볼륨은 부위끼리 비교가 안 된다(스쿼트 100kg×10회 = 1,000, 사이드 레터럴 8kg×15회 = 120이라 하체만 늘 빨갛다). 세트 수는 분석·루틴이 이미 쓰는 단위다. 2D 두 장이면 뒤쪽 근육을 돌리지 않고 본다.
- 근거: 루틴의 회복 제외와 같은 함수(`RecoveryEvaluation`)를 써서 지도와 루틴이 어긋나지 않는다. 계산·API는 3D로 바꿔도 그대로 쓴다.
- 다시 볼 때: 보조근을 칠하거나 3D·여성 그림을 넣을 때(설계서 8장의 다음 과제).
- 관련: #40, #41, 「회복지도_설계서」 2장

## D-02. 주당 일수별 분할(A6)은 하지 않고 분석 탭에 안내 (2026-11-13)

- 상황: 주 3\~4일 운동하는 사용자는 부위마다 "권장 이하"가 계속 뜬다. 주당 일수에 맞춰 분할(전신·상하체 등)을 바꾸면 나아질지 봤다.
- 안: A. 주당 일수별 분할 / **B. 분할은 그대로, 왜 권장 이하가 이어지는지 분석 탭에 안내 ← 선택** / C. 하루 세트 상한을 올림
- 고른 이유: 일주일에 담을 수 있는 양은 `주당 일수 × 하루 상한 18`이라 분할을 바꿔도 총량이 그대로다. 늘릴 길은 하루 상한뿐인데 초보에게 너무 길다.
- 근거: 8주 시뮬레이션 — 주 3일은 부위별 주 6세트, 주 4일 7.5\~9세트, 주 5일 9\~10.5세트. 주 3일 전신은 주 2회가 되지만 6세트 그대로, 주 4일 상·하체는 상체가 주 6세트로 오히려 준다. 하루 상한을 올리면 주 4일 약 22세트, 주 3일 27\~30세트(전에 보류한 A5와 같은 문제).
- 다시 볼 때: 더 채우고 싶다는 요청이 오면 주 4일부터 하루 상한을 조금 올리는 안(루틴 설계서 17장).
- 관련: #45, 「루틴생성_로직_설계서」 17장

- 고른 이유: 균형 판정은 판정 부위(가슴+전면어깨+삼두 대 등+후면어깨+이두)로 센다. 목을 넣으면 판정식이 바뀌고, 목 운동을 하는 사람만 균형이 흔들린다(사용자 1번 a). 한 종목 안에서 기록 방식을 바꾸는 기능은 없어서, 다른 부위처럼 변형을 따로 둔다.

## D-13. 회복 지도의 목 — 고르기 칸은 하나, 분석 부위만 앞·뒤로 (2026-11-27)

- 상황: 회복 지도의 몸 그림에 목 앞·뒤를 칠하기로 했다. 목 종목이 한 부위로 묶여 있어 어떻게 나눌지 정해야 했다.
- 안
  - A. 목은 하나로 두고 앞·뒤 그림을 같은 색으로 — 간단하지만 넥 컬만 해도 목 뒤까지 칠해진다
  - **B. 종목 고르기의 목 칸은 하나, 분석 부위만 목 앞·목 뒤로 ← 선택**
  - C. 고르기 칸까지 목 전면·목 후면 둘로 — 칸이 작게 쪼개지고, 사이드 벤드·트위스트는 어느 칸에도 어색하며, 부위 그림이 하나 더 필요하다
- 고른 이유: 앞·뒤가 따로 칠해지면서 사용자가 찾는 방식("목")은 그대로다.
- 근거
  - 하체가 이미 같은 구조다 — 고르기는 "하체" 한 칸, 분석은 앞허벅지·뒤허벅지, 내 종목 만들기는 하체를 고르면 앞·뒤를 한 번 더 묻는다.
  - 사이드 벤드·트위스트는 앞으로 센다(분석은 종목마다 주동근 하나). 고개 돌리기·옆으로 기울이기를 주로 하는 흉쇄유돌근이 앞 그림의 목 영역이다. 그래서 목 앞 8종, 목 뒤 5종.
  - 그림 라이브러리에 목 영역이 앞·뒤 모두 원래 있었다(#71에서 "자리가 없다"고 한 것은 틀렸다).
- 다시 볼 때: 사이드 벤드를 목 뒤로도 세야 한다는 요청이 오면(보조근을 칠할 때 같이).
- 관련: #73, 「회복지도_설계서」 5장, V20

## D-14. 앱 밖 휴식 알림 — 일반 알림 하나를 "휴식 중" → "휴식 끝"으로 바꾼다 (2026-11-28)

- 상황: 앱 밖에서도 쉬는 시간을 눈으로 확인하고 싶다(사용자). 유튜브 재생처럼 상단바에서 줄어드는 시간을 보고, 누르면 그 종목 화면으로.
- 안
  - A. 유튜브 같은 재생 알림(Media Session) — 웹앱은 실제로 소리를 재생해야 뜬다. 무음을 틀어 흉내 내면 **사용자가 듣던 음악이 멈춘다**
  - B. 네이티브 앱으로 감싸 초 단위로 줄어드는 알림 — 플레이스토어 배포가 필요하고, 아이폰은 그 방식(Live Activity)이 네이티브 앱에서만 된다
  - **C. 일반 알림 하나 — 쉬는 중에 앱을 벗어나면 "휴식 중 · 오후 2:32에 끝나요"를 조용히 띄우고, 끝나면 같은 알림을 "휴식 끝"으로 바꿔 울린다 ← 선택**
- 고른 이유: A는 헬스장에서 음악을 듣는 사용자에게 오히려 불편하다(사용자도 비추천). B는 범위가 너무 크다. C로 "앱 밖에서 쉬는 시간 확인"이라는 목적을 거의 채운다.
- 근거
  - 같은 `tag`로 다시 띄우면 알림이 쌓이지 않고 그 자리에서 바뀌고, `renotify`로 바뀔 때 다시 울린다. 상단바 작은 아이콘도 바꾼다(쉬는 중 타이머 → 끝 아령).
  - 남은 초 대신 **끝나는 시각**을 적는다 — 앱이 뒤로 가면 브라우저가 앱 코드를 멈춰 1초마다 고칠 수 없고, 시각은 한 번 적으면 계속 맞다.
  - 앱을 보고 있을 때는 띄우지 않는다(휴식 띠·끝 소리와 겹친다). 돌아오면 지운다. 설정 › 휴식 타이머 "앱 밖에서도 알림", 알림 권한이 필요해 기본 꺼짐.
  - 알림 버튼(+30초·건너뛰기)은 앱이 뒤에 있을 때 타이머까지 확실히 전해지는지 장담할 수 없어 1차에서 뺐다.
  - 헤드리스 크롬(폭 360·390·430)으로 켜기 → 휴식 → 다른 탭 → "휴식 중" → 끝 → "휴식 끝"(하나만, 다시 울림) → 돌아오면 지움 → 끄면 서비스워커 정리까지 확인.
- 다시 볼 때
  - **1차는 끝을 앱 안 타이머로 알아챈다.** 실제 휴대폰에서 앱이 뒤에 있을 때 "휴식 끝"으로 늦게 바뀌면, 서버가 끝나는 시각에 푸시를 보내는 2차로(웹 푸시는 이미 있다).
  - 알림에서 바로 +30초·건너뛰기를 하고 싶다는 요청이 오면.
- 관련: #74, 「운동기록_방식_설계서」 3.7, 「알림_설계서」 1장

## D-15. 실패 세트 — 숫자 칸에서 세트 종류를 고르고, 실패는 빨간 9/10 (2026-11-28)

- 상황: D-10에서 미룬 실패 세트 기능. 사용자 제안 — 펼치기 패널의 "분석" 줄(워밍업 설정)을 빼고, 세트 번호 칸을 눌러 메인·워밍업·실패를 고르게 한다. 실패는 "10회 목표에 9회"를 빨간 9/10으로. 번호는 그대로 두고 숫자 색만 바꾼다.
- 안 (사용자가 추천대로 고름)
  1. 분석: **A. 해낸 횟수의 본세트로 센다(세트 수·볼륨·1RM) ← 선택** / B. 실패 세트는 따로 뺀다
  2. 다음에 같은 종목을 넣을 때 채우는 값: **A. 목표 횟수의 메인 세트(다시 도전) ← 선택** / B. 해낸 횟수
  3. 시간 종목: **실패 세트 없음(메인·워밍업만) ← 선택** — 횟수가 없다
  4. 휴식 띠·알림의 "N세트": **화면 숫자(줄 위치)와 맞춘다 ← 선택** — 워밍업이 "W"에서 숫자가 되면서 어긋나서
  5. 바디캘린더 `실패 35kg 5/10회`: **실패 세트(5/10)로 ← 선택**. 이미 가져온 것은 목표가 저장돼 있지 않아 본세트 그대로
- 고른 이유: 실패 세트도 실제로 들어 올린 세트다(D-10과 같은 근거). 다음에 채울 때는 목표가 다시 도전할 자리다.
- 근거
  - 저장: 세트에 `target_reps`(V21) — 있으면 실패, `reps`는 해낸 횟수. DB 조건으로 워밍업 아님·목표 > 해낸 횟수. 분석 쿼리는 그대로(워밍업만 뺀다).
  - 화면: 번호는 줄 위치(1·2·3), 메인 기본색·워밍업 주황·실패 빨강. 색만으로 가르지 않게 워밍업 줄에는 "워밍업 · 분석 제외", 실패 줄에는 "9/10"이 있다. 운동 일지·그룹 하루 기록·종목 기록·가져오기 미리보기의 세트 칸도 빨간 9/10(이쪽은 워밍업을 "워밍업" 글자로 둔다 — 설명 줄이 없어서).
  - 실패로 바꾸면 지금 횟수가 목표, 해낸 횟수는 하나 적게 미리. 해낸 횟수는 목표에 닿지 못하게, 목표는 해낸 횟수 아래로 못 내리게 막는다. 일괄 수정으로 목표 이상 횟수를 넣으면 메인 세트로.
- 다시 볼 때: 실패를 분석에 따로 쓰고 싶을 때(예: 다음 기록 미리 채우기에 "지난번 9/10" 표시, 실패 직전 강도로 1RM 보정).
- 관련: #75, V21, 「운동기록_방식_설계서」 3.5, 「기록가져오기_설계서」 결정 13

## D-16. 기록 가져오기의 바꾸기 시트에서도 새 종목 만들기 (2026-11-28)

- 상황: 가져오기 미리보기에서 맞춘 종목·비슷한 종목이 틀려 "바꾸기"를 눌렀는데, 원하는 종목이 없으면 만들 길이 없었다. #65 때 바꾸기 시트(기록 방식으로 거른 종목 고르기)에서는 만들기 버튼을 일부러 뺐다 — 미리보기에 이름이 채워지는 만들기가 따로 있어서였는데, 그건 미등록 운동에만 나온다. 사용자 피드백으로 요청.
- 안: A. 그대로(미등록에만) / **B. 바꾸기 시트 안에서도 목록 맨 아래 "+ 새 종목 만들기" ← 선택** / C. 카드마다 "새 종목 만들기" 버튼을 하나 더
- 고른 이유: 종목 추가 시트와 같은 자리라 익숙하고, 카드에 버튼을 늘리지 않는다.
- 근거: 만들기 창은 원래 이름(과 미등록이면 짐작한 기구·기록 방식)이 채워지고, 그 세트를 담을 수 있는 기록 방식만 누를 수 있다 — 미등록 운동의 만들기와 같다. 만든 종목은 바꾸기로 고른 것과 같아 그 짝을 기억한다(V17).
- 다시 볼 때: 만들기가 두 곳(미등록 카드 버튼, 시트 안)이라 헷갈린다는 의견이 오면 미등록 카드 버튼을 빼는 것.
