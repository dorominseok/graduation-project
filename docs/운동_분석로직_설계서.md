## 0. 설계 원칙

분석 로직을 설계하며 지킨 기준은 다음과 같다.

- **완벽한 운동과학이 아니라 "설명 가능한 합리적 기준"을 목표로 한다.** 운동과학은 세부 사항에 논쟁이 많으므로, 유일한 정답을 추구하기보다 각 결정에 근거를 댈 수 있는 수준을 지향한다.
- **기준값은 공인 문헌(ACSM)에서, 계산 방법은 직접 설계한다.** 논문은 "얼마나 해야 하는가"를 제시하지만 "그것을 데이터에서 어떻게 측정하는가"는 다루지 않으므로, 후자가 본 작품의 고유한 설계 영역이다.
- **과한 정밀도를 피한다.** 근거로 방어할 수 없는 정밀도(예: 소수점 관여도)는 오히려 신뢰를 떨어뜨리므로, 방어 가능한 수준에서 단순화한다.

## 1. 운동량(볼륨) 정량화

### 1.1 단위 — 세트 볼륨

운동량은 **세트 수**로 집계한다. (중량×횟수×세트의 총량, 즉 톤수 방식은 사용하지 않는다.)

**근거**
- 핵심 기능인 부족 판정의 기준(ACSM)이 "부위별 주 N세트" 형태의 세트 단위이므로, 집계도 세트로 해야 기준을 직접 적용할 수 있다.
- 톤수 방식은 맨몸운동(중량 0)에서 계산이 붕괴되고, 종목 간 중량 스케일 차이(레그프레스 vs 사이드 레터럴)로 부위 비교가 왜곡된다.
- 강도(중량) 정보는 버리지 않고 별도 축으로 반영한다(1.3 참조).

### 1.2 세트 카운팅 — 주동근 기준

한 운동이 여러 근육을 사용하더라도, **해당 운동의 주동근(target muscle)** 에만 세트를 집계한다. 보조근(협력근)에 대한 간접 자극은 세지 않는다.

**근거**
- 보조근의 정밀한 관여도를 매길 객관적 근거가 부족하다. 개별 운동의 EMG(근전도) 연구는 존재하나, 측정 조건(그립·강도·숙련도)이 연구마다 달라 직접 비교가 어렵다. 표준 분류 자료(ExRx.net)조차 협력근 간 관여 순위는 제공하지 않는다.
- 따라서 간접 자극을 소수점 가중치로 반영하면 "그 수치의 근거"를 방어하기 어려워진다.
- ACSM 기준 역시 해당 부위를 주 타겟으로 하는 운동을 세는 개념에 가까워, 주동근 카운팅과 정합적이다.

**참고 자료**
- 근육 역할 정의(주동근/협력근/안정근): ExRx.net Kinesiology Glossary (https://exrx.net/Kinesiology/Glossary)
- 운동별 근육 분류: ExRx.net Exercise Directory (https://exrx.net/Lists/Directory)
- ※ ExRx 데이터는 라이선스가 있으므로, 실제 운동 DB는 라이선스가 명확한 오픈소스 데이터셋으로 구축하고 ExRx는 분류 기준 검증용 참고로 활용한다.

**한계 인지**
- 간접 자극을 반영하면 더 정교해질 수 있으나, 본 작품에서는 주동근 기준으로 한정한다. (향후 확장 아이디어로 기록)

**집계 대상 세트 — 워밍업 제외**

세트를 집계할 때 **워밍업 세트는 제외**하고 본세트만 센다. 기록 단계에서 사용자가 워밍업 여부를 표시할 수 있도록 하고(기본값 미표시), 표시된 세트는 볼륨 집계에서 빼낸다.

**근거**
- ACSM의 세트 기준(2.2)은 실패 근처까지 수행하는 본세트를 센 값이므로, 워밍업을 포함해 집계하면 앱의 계산 단위가 기준값의 단위와 달라진다. 이는 "기준값은 문헌에서, 계산 방법은 직접 설계한다"는 0장 원칙에서 계산 방법이 기준값과 어긋나는 경우에 해당한다.
- 워밍업을 포함하면 볼륨이 과대 집계되어, 실제로 부족한 부위가 충분한 것으로 판정된다. 즉 **약점을 놓치는 방향**으로 틀리므로 오판의 성격이 나쁘다.
- 워밍업은 부위에 고르게 분포하지 않고 고중량 복합운동(스쿼트·벤치프레스 등)에 집중되므로, 4장의 비율 판정도 함께 왜곡된다.

**한계 인지**
- 사용자가 워밍업을 표시하지 않고 기록하면 과대 집계가 발생하며, 앱은 이를 판별할 수 없다. 자동 판별은 임계 비율의 근거를 대기 어려워 채택하지 않았다. (「운동기록_방식_설계서」 3.5 참조)

### 1.3 강도 축 — 추정 1RM 대비 %

운동량(양)과 별개로 **강도(질)** 를 함께 측정한다. 강도는 각 세트의 중량이 **추정 1RM의 몇 %인지**로 나타낸다.

**1RM 추정 방식**
- 유저는 평소처럼 [중량 × 횟수]만 기록하며, 앱이 기록으로부터 1RM을 자동 추정한다(예: Epley 공식 등).
- 유저에게 1RM 직접 입력을 요구하지 않는다. 실제 1RM 측정은 부상 위험이 있고, 대부분의 사용자가 자신의 1RM을 모르기 때문이다.

**근거**
- 강도는 회복 주기·부상 위험·자극의 질을 좌우하는 중요한 변수이므로 무시할 수 없다.
- RPE(운동자각도) 방식은 매 세트 주관적 입력을 요구해 사용성이 떨어지고 값이 들쭉날쭉하다. 반면 추정 방식은 기존 기록만으로 계산되어 추가 입력 부담이 없고 값이 일정하다.
- 실제 추정 방식을 채택한 앱을 사용해 본 결과, 사용성 측면에서 추정 방식이 우수하다고 판단하였다.
- ACSM 기준이 강도를 "1RM의 %"로 제시하므로(예: 근력 1RM 80%+), 추정 1RM%가 논문 기준과 직접 연결된다.

**산출 대상 세트**
- 중량·횟수를 기록하는 종목(`measure_type = WEIGHT_REPS`)의 세트만 대상으로 한다.
- **`반복 횟수 ≤ 12`인 세트만 사용**한다. 아래 한계 인지대로 고반복 구간에서 오차가 커지므로, 오차가 큰 구간을 애초에 계산에 넣지 않는다.
- 하루에 같은 종목의 세트가 여럿인 경우, 각 세트의 추정값 중 **최댓값**을 그날의 추정 1RM으로 채택한다.

**한계 인지**
- 추정 1RM은 공식 기반 추정치이며, 특히 고반복 구간에서 오차가 커진다. 따라서 정확한 1RM이 아니라 **강도 경향 파악** 용도로 사용한다.

**표시 방식 — 권고하지 않고 보여주기만 한다**

강도는 "무게를 올려라"와 같은 처방(권고)을 하지 않고, 현황을 표시하여 사용자가 스스로 판단하도록 한다. 이는 부위 약점 판정이 "부족하다"까지만 알리고 강요하지 않는 것과 톤을 맞춘 것이다. 권고까지 가지 않는 이유는, 강도 권고가 의미를 가지려면 목표(근력/근비대) 입력이 필요하고 추정 1RM 오차의 영향을 크게 받는데, 이는 앱을 복잡하게 만드는 데 비해 얻는 것이 크지 않다고 보았기 때문이다.

표시는 두 가지로 나눈다.

| 표시 | 단위 | 시간축 | 위치 | 용도 |
|---|---|---|---|---|
| 추정 1RM 추이 | kg | 있음(날짜별) | 통계 화면 | 성장 추세 확인 |
| 세트별 강도 | % | 없음(그 날 기록 내) | 기록 화면 | 그 시점 강도 스냅샷 |

- **추정 1RM(kg) 추이**: 운동별로 추정 1RM이 날짜에 따라 어떻게 변하는지 그래프로 보여준다. kg 단위로 표시하는 이유는, 사용자가 강해질수록 기준(1RM)이 계속 변하므로 성장 추세는 절대값(kg)으로 보아야 명확하기 때문이다.
- **세트별 강도(%)**: 그 날, 그 운동 기록 안에서만 각 세트가 그 날 추정 1RM의 몇 %였는지 표시한다. 날짜 간 이어서 그리지 않는다.

**왜 % 는 시간 추이로 그리지 않는가 (한계 인지)**
- 강도 % = 중량 ÷ 추정 1RM인데, 1RM은 사용자가 강해질수록 계속 상승한다. 따라서 같은 중량이라도 시간이 지나면 % 는 오히려 낮아진다(예: 70kg이 78% → 70%). 이를 시간축 그래프로 그리면 "강해졌는데 강도가 떨어진 것처럼" 보여 오해를 부른다.
- 따라서 성장은 kg(추정 1RM)로, % 는 해당 날짜의 스냅샷으로 분리하여 표시한다.

### 1.4 양·질 이원 진단

위 두 축을 조합해, 처방이 아니라 현황 파악 차원에서 다음과 같이 구분해 보여줄 수 있다.

- 세트는 충분하나 강도(추정 1RM 대비 %)가 낮은 편 → 강도 현황으로 표시 (판단은 사용자 몫)
- 세트가 부족 → "볼륨 부족"으로 판정(2장)

## 2. 부족 근육 판정

### 2.1 기간 — 최근 4주 평균

판정 부위별 세트를 **최근 4주간 집계한 뒤 4로 나누어 "주당 평균 세트"** 로 환산해 판정한다. (판정 부위의 정의는 2.3 참조)

**근거**
- ACSM 기준이 "주 단위"이므로 주당 값으로 환산해야 한다.
- 최근 7일 고정 방식은 하루 단위로 판정이 요동쳐(어제 안 한 부위가 오늘 부족으로 표시되는 등) 유저에게 혼란을 준다.
- 운동 볼륨은 단기 변동이 크므로, 4주 평균이 실제 운동 경향을 안정적으로 반영한다. 근거 문헌들도 수 주 단위 누적으로 효과를 논한다.

**한계 인지**
- 4주 평균은 최근의 급격한 변화에는 상대적으로 둔감하다.

### 2.2 임계값 — 4단계 구간

주당 평균 세트를 다음 구간으로 분류한다.

| 주당 평균 세트 | 상태 | 처리 |
|---|---|---|
| 4세트 미만 | **부족** | 우선 보완 대상 |
| 4~10세트 | **권장 이하** | 여유 시 보완 |
| 10~20세트 | **최적** | 유지 |
| 20세트 초과 | **과다** | 과훈련 경고 |

**근거**
- ACSM 권고(최소 유효 4세트, 최적 10~20세트, 20세트 초과 시 수익 감소)를 그대로 구간화하였다.
- "부족(4세트 미만, 확실한 문제)"과 "권장 이하(4~10세트, 개선 여지)"를 분리함으로써, 단일 임계값보다 더 풍부한 진단 정보를 제공한다.

### 2.3 판정 단위 및 집계 조건

1.2에서 정한 대로 각 운동의 주동근 기준으로 집계한 세트를 사용하며, 다음 조건을 만족하는 세트만 대상으로 한다.

**판정 부위 목록**

판정 단위는 `exercises.body_part`(저장·검색용 6종)가 아니라 `exercises.primary_muscle` 기반의 **근육군 9종**이다. 4장의 균형 판정 계산식이 밀기(가슴+전면어깨+삼두), 당기기(등+후면어깨+이두) 등 `body_part`보다 잘은 입자를 요구하기 때문이다. 상세 근거는 「설계 변경 로그」 LOG-09 참조.

| 판정 부위 | 구성 `primary_muscle` |
|---|---|
| CHEST | chest |
| BACK | lats, middle back, traps, lower back |
| DELT_FRONT | shoulders (오버헤드 프레스·전면 레이즈·측면 레이즈 계열) |
| DELT_REAR | shoulders (후면 델트 계열) |
| TRICEPS | triceps |
| BICEPS | biceps |
| QUADS | quadriceps, abductors, adductors |
| POSTERIOR | hamstrings, glutes |
| CORE | abdominals |

**부족 판정 제외**: `calves`, `forearms`

두 근육군은 ACSM 권고가 별도 단위로 다루지 않으며, 다수의 사용자가 별도 훈련하지 않으므로 미수행을 약점으로 판정할 근거가 없다. 0장 "근거로 방어할 수 없는 정밀도를 피한다"에 따른 결정이다. 다만 4장의 하체 볼륨 합산에는 종아리를 포함한다(계산식에 명시되어 있음).

| 조건 | 내용 | 근거 |
|---|---|---|
| 완료된 세션 | 진행 중(DRAFT)인 세션은 제외 | 운동 중인 세션이 섞이면 그날의 판정과 루틴 추천이 요동친다 |
| 본세트 | 워밍업 표시된 세트는 제외 | 1.2 참조 |
| 기간 | 수행 일자 기준 최근 4주 | 2.1 참조. 기록 저장 시각이 아니라 수행 일자를 기준으로 한다 |

> 사후 입력(BACKFILL)된 기록은 볼륨 집계에 **포함**한다. 실제로 수행한 운동이므로 제외하면 오히려 부족으로 오판된다. (운동 시간 집계에서만 제외하며, 「운동기록_방식_설계서」 4.3 참조)

## 3. 빈도 판정 (Optional — 보류)

ACSM은 볼륨과 별개로 "주요 근육군 주 2회 이상 자극"을 강조한다. 이에 따라 볼륨은 충분하나 주 1회에 몰아서 수행하는 경우를 감지하는 빈도 판정을 고려하였다.

**설계 방향(구현 시)**
- 볼륨 판정보다 우선순위를 낮게 두어 계층화한다. 볼륨이 부족한 부위는 "세트를 늘려라"만 안내하고, 볼륨이 충분한 부위에 한해 "주 2회로 나눠라"를 안내하여 조언이 중복되지 않게 한다.

**보류 사유**
- 볼륨 판정이 핵심이며 빈도는 그 위에 얹는 정밀화이다. 없어도 작품이 성립하므로, 볼륨 판정을 완성한 뒤 여유가 있을 때 구현하는 **Optional 항목**으로 분류한다.
- 구현 비용 자체는 작다(기존 기록의 날짜를 부위별로 카운트하는 수준). 따라서 시간 여유가 생기면 우선적으로 추가할 후보이다.

## 4. 균형 판정

부족 판정(2장)이 각 부위의 절대량을 본다면, 균형 판정은 **대응하는 근육군 쌍의 비율**을 본다. 예를 들어 가슴과 등이 각각 최적 범위에 있더라도, 한쪽이 다른 쪽보다 지나치게 많으면 불균형으로 볼 수 있다. 이러한 불균형은 미관이 아니라 **부상 위험**과 연관되므로 별도 지표로 다룬다.

### 4.1 대상 근육군 쌍

두 가지 쌍을 판정 대상으로 한다.

| 쌍 | 구성 | 채택 이유 |
|---|---|---|
| 밀기 vs 당기기 | 밀기(가슴·전면어깨·삼두) / 당기기(등·후면어깨·이두) | 밀기 편중이 어깨 부상과 연관된다는 근거가 확실하며, 유저가 스스로 인지하기 어려운 불균형이라 앱이 감지하는 가치가 크다 |
| 상체 vs 하체 | 상체(밀기+당기기) / 하체(대퇴사두·햄스트링·둔근·내전근·외전근·종아리) | 흔한 불균형이며 직관적이라 유저 이해를 돕는다 |

**제외 항목**
- **좌우 균형**: 부상 연관 근거는 있으나(좌우 15% 이상 차이 시 하지 부상 위험 증가), 유저가 좌우를 분리해 기록하지 않으므로 앱 데이터로 측정이 불가능하여 제외한다.
- **대퇴사두 vs 햄스트링(앞뒤 허벅지)**: 근거는 강하나(비율 불량 시 ACL 부상 위험 증가) 세밀한 분류가 필요하여 Optional로 둔다.

### 4.2 판정 기준 — 2배 초과 시 경고

특정 이상 비율(예: 1:1)을 강제하지 않고, **명백한 불균형만 보수적으로 감지**한다.

```
큰 쪽 세트 ÷ 작은 쪽 세트
- 2배 이하  → 정상
- 2배 초과  → 불균형 경고
```

**근거**
- 실측 연구에서 건강한 일반 성인의 자연스러운 밀기:당기기 강도 비율은 약 1.5:1(남성 1.57:1)로, **밀기가 우세한 것이 정상**이다. 따라서 1:1을 기준으로 삼으면 정상인 다수를 불균형으로 오판하게 된다.
- 이에 정상 범위(약 1.5배)를 명백히 벗어나는 **2배 초과**만 경고하도록 설정하여 오탐(false positive)을 최소화하였다.
- 상하체 쌍은 밀기/당기기만큼의 실측 기준이 정립되어 있지 않으므로, 일관성을 위해 동일하게 2배 초과 기준을 적용한다.

**한계 인지**
- 이상적 비율에 대해서는 문헌 간 견해차가 있다(1:1 ~ 1.5:1). 본 작품은 정밀한 최적 비율을 제시하기보다 명백한 이상만 감지하는 보수적 접근을 택하였다.

### 4.3 계산 재료

새로운 데이터 없이 앞서 산출한 주동근 기준 세트 볼륨(최근 4주 평균, 1장·2장 참조)을 그룹으로 묶어 비율을 산출한다. 각 항목은 2.3의 판정 부위에 대응한다.

```
밀기 세트   = CHEST + DELT_FRONT + TRICEPS
당기기 세트 = BACK + DELT_REAR + BICEPS
상체 세트   = 밀기 + 당기기
하체 세트   = QUADS + POSTERIOR + calves

비율 = 큰 쪽 ÷ 작은 쪽
```

`calves`는 부족 판정 대상은 아니나(2.3) 하체 볼륨 합산에는 포함한다. 하체 총량을 실제보다 적게 잡으면 상하체 불균형을 과다 경고하게 되기 때문이다.

**어깨 전·후면 배분**

free-exercise-db는 `primaryMuscles`를 `shoulders` 하나로만 제공하며 세부를 구분하지 않는다. 따라서 종목 정제 시 부여한 동작 패턴을 기준으로 배분한다.

| 동작 패턴 | 배분 | 근거 |
|---|---|---|
| 오버헤드 프레스 | DELT_FRONT | `force = push` |
| 전면 레이즈 | DELT_FRONT | 명시적 |
| 측면 레이즈 | DELT_FRONT | 아래 별도 근거 |
| 후면 델트 | DELT_REAR | 명시적 |

측면 레이즈(중간 삼각근)는 밀기·당기기 어느 쪽에도 해부학적으로 대응하지 않으나, 계산식에 자리가 필요하므로 밀기로 배정하였다. 실제 훈련에서 어깨 프레스와 함께 밀기 세션에 배치되는 것이 일반적이며, 당기기에 넣을 경우 당기기 볼륨이 부풀려져 **당기기 부족을 놓치는 방향**으로 오판하게 되기 때문이다.

**미해결 사항**

이 배분 정보는 현재 DB에 저장되어 있지 않다. `exercises` 테이블에는 `primary_muscle = shoulders`만 존재하므로, 구현 시점에 다음 중 하나를 선택해야 한다.

| 방안 | 내용 |
|---|---|
| 컬럼 추가 | `exercises`에 `movement_pattern` 또는 `delt_region` 컬럼 신설 |
| 코드 매핑 | 판정 로직에 종목 ID 목록을 상수로 보유 |

컬럼 추가가 데이터와 로직을 분리한다는 점에서 바람직하나, 마이그레이션과 정제 데이터 갱신이 따른다. 10월 분석 로직 구현 시 확정한다.

## 7. 지도교수 피드백 및 반영 방향

계획서 제출 후 받은 지도교수 의견은 다음과 같으며, 개발은 아래 순서를 따른다.

> 단계별 추진을 권장함.
> 1. 운동 기록 방식을 구체화해 충실한 기록을 확보할 것
> 2. 기록을 바탕으로 다양한 측면의 분석을 제공할 것 (① 그래프 등으로 운동 실적 시각화 ② LLM을 통한 평가 제공)
> 3. 마지막으로 부족한 부분을 추천하도록 구성할 것

### 7.1 기존 계획과의 관계

제시된 3단계는 기존 개발 일정(운동 기록 → 통계·그래프 → 약점 분석 → 루틴 추천)과 순서가 일치하므로, 전체 구조는 그대로 유지한다. 다만 다음 두 가지를 보강한다.

### 7.2 보강 ① — 운동 기록 방식 구체화 ✅ 완료 (2026-08-02)

분석과 추천은 모두 기록 데이터 위에서 동작하므로, 기록이 부실하면 이후 단계가 무의미해진다. 이에 설계 단계에서 기록 방식을 우선 구체화하였다.

검토 항목과 결정 결과는 다음과 같으며, 상세 근거는 **「운동기록_방식_설계서.md」** 에 정리하였다.

| 검토 항목 | 결정 |
|---|---|
| 세트별 입력 방식 | 세트 1개 = 1행 저장. 요약 입력 미사용(세트별 강도 % 산출에 필요). 3단 프리필로 입력 부담 완화 |
| 운동 시간 기록 방식 | 세트 저장 시각 기반 자동 산출 + 이상치 캡. 별도 조작 없음 |
| 기록 누락·수정 처리 | 미완료 세션(DRAFT) 유지, 과거 기록 사후 입력 허용, 온디맨드 집계로 수정 자동 반영 |
| 데이터 구조 | 계획서 4.4의 `workout_logs`를 `workout_sessions` / `workout_sets` 2계층으로 분해 |
| 본 문서에 반영된 사항 | 워밍업 세트 제외(1.2), 1RM 산출 대상 세트(1.3), 집계 조건(2.3) |

### 7.3 보강 ② — LLM 기반 분석 평가 제공

기존 설계에서 LLM은 루틴 생성(추천 단계)에만 관여하였으나, 피드백에 따라 **분석 단계에서도 평가·해설을 제공**하는 기능을 추가로 검토한다.

- **내용**: 자체 로직이 산출한 판정 결과(부위별 볼륨, 부족·불균형, 추정 1RM 추이)를 LLM이 자연어로 해설
- **예시**: "최근 4주간 등 볼륨이 주 3세트로 권장 범위에 미치지 못하며, 가슴 대비 비중이 낮습니다."
- **위치**: 약점 분석 결과 조회 화면 (통계 화면)
- **원칙**: 판정 자체는 자체 로직이 수행하고, LLM은 그 결과를 설명하는 역할만 담당한다. 추천 단계에서 LLM을 통제하는 방식과 동일하게, 분석 수치를 LLM이 임의로 해석하거나 바꾸지 않도록 제한한다.
- **이점**: 추천을 받기 전에도 자신의 운동 상태를 이해할 수 있어, 단계 2만으로도 사용자에게 가치를 제공할 수 있다.
