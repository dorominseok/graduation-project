# 회복 지도 설계서

> 2026-11-10 작성. 분석 탭의 "통계" 서브탭 자리에, 부위별 회복 상태를 앞·뒤 인체 그림으로 보여 준다.
> 다른 세션이 이어 받을 때 이 문서만 읽고 시작할 수 있게 결정·규칙·완료 기준을 모두 적는다.

---

## 1. 목적

- 어느 부위가 아직 회복 중인지 한눈에 보여 준다. 오늘 운동할 부위를 고를 때 근거가 된다.
- **오늘의 루틴과 같은 판정을 쓴다.** 루틴은 오늘 포함 2일 안에 한 부위를 뺀다(`app.routine.recovery-days`). 지도에서 "회복됨"인데 루틴이 그 부위를 빼면 두 화면이 서로 다른 말을 한다.
- 통계 서브탭(종목별 추정 1RM 추이)은 종목 상세 화면에도 같은 패널이 있어서 빼도 잃는 기능이 없다.

## 2. 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 기준 | **날짜 + 세트 수**. 무게는 쓰지 않는다 | 무게×횟수는 부위끼리 비교가 안 된다. 스쿼트 100kg×10회는 1,000, 사이드 레터럴 8kg×15회는 120이라 하체만 늘 빨갛게 나온다. 세트 수는 분석·루틴이 이미 쓰는 단위다 |
| 시간 단위 | **날짜**(`performed_on`) | 지난 기록을 나중에 입력하면 저장 시각이 실제 운동 시각과 다르다. 분석·루틴도 날짜로 센다 |
| 회복 중 | 오늘 포함 `recovery-days`(2)일 안에 한 부위 | 루틴의 회복 제외와 **같은 함수**를 쓴다(`RecoveryEvaluation.recovering`) |
| 많이 함 | 회복 중 기간의 본세트 합이 `per-muscle-max-sets`(6) 이상 | 루틴이 한 부위에 한 번에 주는 최대치를 채웠으면 많이 한 것으로 본다 |
| 이름 | "회복 상태", 서브탭 이름 "회복" | 피로도는 잰 값이 아니라 기록으로 짐작한 값이다. 근거를 보여 주는 앱 성격에 맞게 단정하지 않는 이름을 쓴다 |
| 색 | 빨강 → 주황 → 노랑 → 기본 회색, 범례를 붙인다 | 빨강→초록은 색약 사용자가 구분하기 어렵다 |
| 부위 | 앱의 11개(판정 9 + 표시 전용 종아리·전완). 종목의 **주동근만** 칠한다 | 분석과 같은 단위. 보조근은 종목 데이터에 없다 — 보강은 다음 과제(8장) |
| 그림 | `react-muscle-highlighter` 1.2.0(MIT)의 남성 앞·뒤 SVG 경로를 복사해 자체 컴포넌트로 그린다 | 곡선 경로라 품질이 좋고, 의존성으로 넣지 않으면 색·터치·유리 테마를 직접 다룰 수 있다. 라이선스 문구를 함께 둔다 |
| 2D / 3D | 2D 앞·뒤 두 장 | 뒤쪽 근육을 돌리지 않고 본다. 계산·API는 3D로 바꿔도 그대로 쓴다 |

## 3. 계산

부위마다 최근 `app.analysis.weeks`(4)주 안의 마지막 운동일과, 회복 중 기간(오늘 포함 R일, R = `recovery-days`)의 본세트 수를 센다. 세트 조건은 분석과 같다 — 워밍업 제외, `performed_on` 기준, 오늘 체크한 세트 포함.

`daysSince` = 오늘 − 마지막 운동일

| 상태 | 조건 | 색 | 화면 표기 |
|---|---|---|---|
| `HIGH` | `daysSince < R` 이고 최근 세트 ≥ 6 | 빨강 | 회복 중 · 많이 함 |
| `MEDIUM` | `daysSince < R` 이고 최근 세트 < 6 | 주황 | 회복 중 |
| `LOW` | `daysSince = R` | 노랑 | 거의 회복 |
| `RECOVERED` | `daysSince > R`, 또는 4주 안에 기록 없음 | 회색 | 회복됨 |

- R = 0이면 회복 중인 부위가 없다(전부 `RECOVERED`). 루틴도 그때는 회복 제외를 하지 않는다.
- 예시(R = 2, 오늘 11/10): 어제 가슴 7세트 → `HIGH`. 오늘 이두 3세트 → `MEDIUM`. 11/8에 하체 → `LOW`. 11/6에 등 → `RECOVERED`.
- 어깨는 분석처럼 `delt_region`으로 앞(전·측면)·뒤(후면)를 가른다. `delt_region`이 없는 어깨 종목은 세지 않는다(분석 8.1과 같다).

## 4. API

`GET /api/v1/analysis/recovery` — 인증 필요, 파라미터 없음(오늘 기준).

```json
{
  "date": "2026-11-10",
  "recoveryDays": 2,
  "heavySets": 6,
  "muscles": [
    { "key": "CHEST", "label": "가슴", "judged": true,
      "state": "HIGH", "stateLabel": "회복 중 · 많이 함",
      "lastTrainedOn": "2026-11-09", "daysSince": 1, "recentSets": 7 }
  ]
}
```

| 필드 | 설명 |
|---|---|
| `muscles` | 11개 부위가 `MuscleGroup` 순서대로 **항상 모두** 온다. 기록이 없어도 빠지지 않는다 |
| `judged` | 부족 판정 대상인지. 종아리·전완은 `false`(분석과 같다) |
| `lastTrainedOn` · `daysSince` | 최근 4주 안에 기록이 없으면 둘 다 `null` |
| `recentSets` | 오늘 포함 `recoveryDays`일 동안의 본세트 수 |
| `recoveryDays` · `heavySets` | 화면이 범례·상세 문구("2일 안에 6세트 이상")를 만들 때 쓴다 |

## 5. 화면

- 분석 탭 서브탭: **약점 | 회복**. 예전 주소 `?tab=stats`로 들어오면 회복을 연다.
- 앞·뒤 그림을 나란히 놓는다. 휴대폰 폭 360px에서도 두 장이 한 줄에 들어가게 한다. 아래에 4단계 범례.
- 부위를 누르면 아래 카드에 부위 이름, 상태, 마지막 운동(날짜·며칠 전), 최근 세트, 회복 중이면 "오늘 루틴에서 빠져요"를 보여 준다.
- 그림만으로는 화면 읽기 프로그램이 알 수 없으므로 회복 중인 부위를 글로도 나열한다(예: "회복 중: 가슴, 삼두").
- 4주 안에 기록이 없으면 그림은 전부 회색이고 "운동을 기록하면 회복 상태가 보여요"를 띄운다.
- 앱이 세지 않는 곳(머리·목·손·발·무릎·정강이 앞)은 실루엣 기본색으로 칠하고 누를 수 없다.

**그림 영역 → 부위**

| 그림 | 영역(slug) | 부위 |
|---|---|---|
| 앞 | chest | 가슴 `CHEST` |
| 앞·뒤 | trapezius / upper-back, lower-back(뒤) | 등 `BACK` |
| 앞 | deltoids | 어깨 전·측면 `DELT_FRONT` |
| 뒤 | deltoids | 어깨 후면 `DELT_REAR` |
| 앞·뒤 | triceps | 삼두 `TRICEPS` |
| 앞 | biceps | 이두 `BICEPS` |
| 앞·뒤 | quadriceps(앞), adductors | 앞허벅지 `QUADS` |
| 뒤 | gluteal, hamstring | 뒤허벅지·둔근 `POSTERIOR` |
| 앞 | abs, obliques | 코어 `CORE` |
| 앞·뒤 | calves | 종아리 `CALVES` |
| 앞·뒤 | forearm | 전완 `FOREARMS` |

## 8. 다음 과제 (이번에 하지 않음)

- 보조근 반영 — 종목 데이터에 보조근을 더해야 한다(원본 free-exercise-db에 `secondaryMuscles`가 있다). 벤치프레스가 삼두·앞어깨도 칠하게 된다
- 3D 모형 — 근육이 나뉜 모형 파일·라이선스·용량 문제가 먼저다
- 여성 그림 선택 — 같은 패키지에 경로가 있다. 프로필에 성별이 없어 설정이 필요하다
- 무게·강도 반영 — 같은 세트라도 무거운 날을 더 지친 것으로 보려면 사용자별 기준(추정 1RM 대비)이 필요하다
