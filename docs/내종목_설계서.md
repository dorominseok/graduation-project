# 내 종목 설계서

> 2026-11-18 작성. 사용자가 직접 만드는 종목 — 친구들 사용 후기에서 나온 요청 1번("부족한 종목 추가").
> 화면은 로컬 시안을 세 번 고쳐 사용자와 정했다(브랜치 `proto/custom-exercise`, 올리지 않음 — 화면 코드를 만들 때 가져다 쓴다).
> 요청 4번(다른 앱 기록 붙여넣기)은 우리 DB에 없는 종목을 이 기능으로 만든다. 그쪽은 따로 설계한다.
> 같은 날 서버(8장 PR 1, #62) 구현 — 5장을 구현에 맞췄다(고치기는 PUT, 탈퇴는 기록을 먼저 지움).
> 같은 날 화면(PR 2) 구현 — 3.4 고치기·지우기 자리를 종목 정보 아래로, 3.5에 상세 그림 상자.
> 2026-11-20 운동 부위 "목" 추가 — 부위 선택지 14개(3번 결정·3장 폼). 목으로 만든 종목은 동작 없음.
> 2026-11-27 목도 하체처럼 앞·뒤를 한 번 더 고른다(목 앞 `front neck`·목 뒤 `back neck`, 회복 지도가 앞·뒤를 따로 칠한다). 요청 필드 `legSide` → `side`(예전 이름도 받음). 그 전에 만든 목 종목은 앞으로 옮겼다(V20).
> 다른 세션이 이어 받을 때 이 문서만 읽고 시작할 수 있게 결정·규칙·완료 기준을 모두 적는다.

## 1. 무엇을 하나

- 기본 종목(274종)에 없는 운동을 사용자가 직접 만든다. **만든 사람 계정에서만 보인다.** 그림은 없다(그림을 올리려면 외부 저장소가 필요해 하지 않는다).
- 만든 종목은 기본 종목과 똑같이 기록하고, **분석·약점 판정·회복 지도·1RM 추이에 들어간다.**
- 오늘의 루틴에는 들어가지 않는다(결정 8).

## 2. 결정

| # | 결정 | 이유 |
|---|---|---|
| 1 | 같은 `exercises` 테이블에 주인(`owner_id`)을 두고 넣는다 | 세트·분석·1RM·기록 조회가 모두 종목 id로 이어져 있어, 같은 테이블이면 손대지 않고 그대로 동작한다. 따로 두면 그 모든 곳이 두 테이블을 봐야 한다 |
| 2 | 부위는 반드시 고른다 — "분류 안 함" 없음 | 사용자 결정. 우리 앱에서 분류가 안 되는 근력 운동이 딱히 없고, 분석에서 빠지는 종목을 만들 이유가 없다 |
| 3 | 부위 선택지는 부위 고르기 화면과 같은 14개(목은 2026-11-20에 더함). **하체·목만** 앞·뒤(앞허벅지·뒤허벅지, 목 앞·뒤)를 한 번 더 고른다(목은 11-27부터) | 어디서 만들기를 눌러도 그 이름이 그대로 미리 눌려 있게. 분석은 하체를 앞허벅지·뒤허벅지·둔근으로 나눠 보므로 하체 하나로는 판정할 수 없다 |
| 4 | "내 종목" 폴더를 따로 두지 않는다. **만든 자리에 나타난다** — 계열 안에서 만들면 그 계열, 계열 없이 만들면 그 부위 계열 목록 맨 아래 "내 종목" 가로 칸 | 사용자 결정(시안 3차). 폴더를 하나 더 두면 찾으러 한 번 더 들어가야 하고, 계열 없는 종목을 계열 목록에 반 칸 카드로 늘어놓으면 붕 떠 보인다 |
| 5 | 만들기 버튼 "+ 새 종목 만들기"는 **부위 고르기·계열 목록·종목 목록 맨 아래.** 누른 자리의 부위(와 계열)가 미리 골라져 있다 | 사용자 결정. 이름을 "종목 추가"로 하지 않은 것은 이 시트의 제목 "종목 추가"(= 오늘 기록에 넣기)와 헷갈리지 않게 |
| 6 | 종목 카드의 그림 자리는 빈칸. 회색 덤벨은 "내 종목" 가로 칸의 그림 자리에만. 종목 상세의 그림 상자도 빈칸 그대로 | 사용자 결정. 그림 없는 기본 종목 14종이 이미 이렇게 보인다 |
| 7 | 파란 "내 종목" 알약을 붙인다 | 초록 "추가됨"(오늘 기록에 넣음, #60)과 한눈에 구분되게 |
| 8 | **오늘의 루틴 후보에 넣지 않는다**(기록·즐겨찾기 후보, 교체 후보 포함) | 루틴 규칙과 LLM은 다듬어 둔 기본 종목(흔한 정도·입문 순위·기구 다양성)을 전제로 짠다. 기록은 분석에 들어가므로 약점 판정에는 반영된다 |
| 9 | 지우기: **기록이 없으면 지우고, 있으면 숨긴다.** 숨긴 이름으로 다시 만들면 그 종목을 되살린다 | 지난 기록의 종목 이름이 사라지면 안 된다. 되살리면 지난 기록이 다시 이어진다 |
| 10 | 이름은 1\~50자. 기본 종목 이름이나 내 다른 종목 이름과 같으면 안 된다(앞뒤 공백을 걷고 여러 칸 띄어쓰기는 한 칸으로 보고 비교) | 고를 때, 그리고 4번 붙여넣기에서 이름으로 맞출 때 헷갈린다 |
| 11 | 한 계정에 100개까지(숨긴 것 포함) | 끝없이 쌓이지 않게. 100개면 실제로 넘을 일이 없다 |
| 12 | 기록 방식은 기구로 기본값 — 맨몸·풀업바는 횟수만, 나머지는 무게 × 횟수. 바꿀 수 있다 | 대부분 이 짝이라 한 번 덜 누른다 |

## 3. 화면 (시안 3차 기준)

### 3.1 만들기 버튼

| 자리 | 미리 골라지는 것 | 만든 종목이 나타나는 곳 |
|---|---|---|
| 부위 고르기 맨 아래(두 칸을 한 줄로) | 없음 | 고른 부위의 "내 종목" 가로 칸 |
| 계열 목록 맨 아래(예: 어깨 전·측면) | 그 부위 | 그 부위의 "내 종목" 가로 칸 |
| 종목 목록 맨 아래(예: 어깨 전·측면 › 레터럴 레이즈) | 그 부위와 계열 | 그 계열 안(다른 종목들과 함께) |

- 버튼은 점선 버튼(기록 화면 "+ 세트 추가"와 같은 모양).
- 만들기 창에서 부위를 다른 것으로 바꾸면 계열은 버리고 바꾼 부위의 "내 종목" 칸으로 간다 — 계열은 부위에 딸려 있다.
- 검색·최근 사용·즐겨찾기 탭에는 버튼을 두지 않는다(부위를 미리 고를 수 없다).

### 3.2 "내 종목" 가로 칸

- 그 부위에 계열 없이 만든 종목이 하나라도 있을 때만, 계열 목록 맨 아래(만들기 버튼 바로 위)에 나온다.
- 계열 카드와 같은 모양: 그림 자리에 회색 바탕 덤벨, 이름 "내 종목"(파랑), 오른쪽에 "N가지 ›".
- 누르면 "어깨 전·측면 · 내 종목" 목록 — 종목 카드 두 칸 배치, 맨 아래 만들기 버튼.

### 3.3 만들기 창

시트 안에서 한 단계로 열린다("← 새 종목 만들기"). 위에서부터:

1. **이름** — 입력칸, 1\~50자.
2. **운동 부위** — "약점 판정에 쓰여요". 버튼 14개(세 칸씩). 하체를 고르면 아래에 "하체는 분석에서 앞·뒤를 나눠 봐요"와 앞허벅지·뒤허벅지 버튼. 목도 같은 자리에 "목은 분석에서 앞·뒤를 나눠 봐요 (옆·돌리기는 앞)"와 목 앞·목 뒤 버튼(2026-11-27). 부위를 바꾸면 앞·뒤는 다시 고른다.
3. **기구** — 바벨·덤벨·머신·케이블·맨몸·풀업바(세 칸씩).
4. **기록 방식** — "기구를 고르면 정해져요". 무게 × 횟수·횟수만·맨몸 + 추가 무게·시간(두 칸씩).
5. **버튼** — 기록 화면 시트에서는 "만들고 오늘 기록에 넣기", 종목 둘러보기 화면에서는 "만들기". 이름·부위(하체·목이면 앞뒤까지)·기구·기록 방식이 다 차야 눌린다.
6. **아래 안내** — "어깨 전·측면 › 레터럴 레이즈에 들어가요 · 내 계정에서만 보여요"(들어갈 자리를 그대로).

고르는 버튼은 알림 설정의 요일 버튼과 같은 모양이다.

- 만든 뒤: 기록 화면 시트에서는 오늘 기록에 넣고 시트는 처음 단계(부위 고르기)로 돌아간다(#60과 같은 흐름). 종목 둘러보기 화면에서는 그 종목 상세로 간다.
- 오류(이름 겹침, 100개 초과)는 이름 칸 아래 빨간 글씨.

### 3.4 고치기·지우기

- **종목 상세(ⓘ)** 에서 내 종목이면 종목 정보 표 바로 아래에 "고치기"와 "지우기" 버튼 두 개를 둔다(지우기는 빨간 글씨). 처음엔 오른쪽 위로 정했는데, 머리줄에 즐겨찾기 별이 있어 버튼 둘을 더 넣으면 좁다.
  - 고치기: 같은 창이 값이 채워진 채 열린다. 버튼은 "저장".
  - 지우기: 확인 시트. 기록이 있으면 "목록에서 숨기고 지난 기록은 남겨요", 없으면 "지울까요?".
- 부위를 고치면 지난 기록도 새 부위로 분석된다(분석은 그때그때 기록으로 계산한다). 창에 "지난 기록도 새 부위로 계산돼요"를 적는다.

### 3.5 다른 화면에서

| 화면 | 내 종목 |
|---|---|
| 검색·최근 사용·즐겨찾기 | 기본 종목과 함께, 파란 "내 종목" 알약 |
| 부위 고르기 칸의 숫자 | 내 종목만큼 늘어난다(내 계정에서만) |
| 계열 카드의 "N가지" | 그 계열 안에 만든 내 종목까지 센다 |
| 기록 화면(카드·세트 입력·휴식 타이머) | 기본 종목과 같다 |
| 종목 상세·종목 기록 페이지 | 기본 종목과 같다. 그림 상자는 같은 크기의 빈 상자 — 영문명이 없어 그림 자리를 그리지 않으면 상자가 선 하나로 납작해져서, 빈 칸 둘을 둔다 |
| 그룹 멤버의 하루 기록 | 친구의 내 종목도 이름 그대로 보인다(그림 없음). 친구는 그 종목을 고르거나 열 수 없다 |
| 오늘의 루틴 | 나오지 않는다 |

## 4. 데이터 — `V16__custom_exercises.sql`

```sql
ALTER TABLE exercises ADD COLUMN owner_id BIGINT REFERENCES users(id) ON DELETE CASCADE;
ALTER TABLE exercises ADD COLUMN hidden_at TIMESTAMPTZ;

-- 기본 종목끼리만 이름이 겹치면 안 된다. 내 종목은 사람마다 따로
ALTER TABLE exercises DROP CONSTRAINT uq_exercises_name_ko;
CREATE UNIQUE INDEX uq_exercises_builtin_name ON exercises (name_ko) WHERE owner_id IS NULL;
CREATE UNIQUE INDEX uq_exercises_owner_name ON exercises (owner_id, name_ko) WHERE owner_id IS NOT NULL;
```

- **시드:** `R__seed_exercises.sql`의 `ON CONFLICT (name_ko)`를 `ON CONFLICT (name_ko) WHERE owner_id IS NULL`로 바꾼다(부분 유일 인덱스를 고르게). 생성 스크립트 `scripts/gen_exercise_seed.py`도 같이 고친다. 반복 마이그레이션은 버전 마이그레이션 뒤에 돌아 순서 문제가 없다.
- **부위 → 저장 값**(기본 종목의 쓰임과 같게):

| 부위 | `primary_muscle` | `delt_region` | `body_part` | `push_pull` |
|---|---|---|---|---|
| 가슴 | chest | | CHEST | PUSH |
| 등 | lats | | BACK | PULL |
| 어깨 전·측면 | shoulders | FRONT | SHOULDERS | PUSH |
| 어깨 후면 | shoulders | REAR | SHOULDERS | PULL |
| 승모근 | traps | | BACK | PULL |
| 삼두 | triceps | | ARMS | PUSH |
| 이두 | biceps | | ARMS | PULL |
| 전완 | forearms | | ARMS | PULL |
| 복부 | abdominals | | CORE | PULL |
| 허리 | lower back | | BACK | PULL |
| 엉덩이 | glutes | | LEGS | PUSH |
| 하체 › 앞허벅지 | quadriceps | | LEGS | PUSH |
| 하체 › 뒤허벅지 | hamstrings | | LEGS | PULL |
| 종아리 | calves | | LEGS | PUSH |
| 목 › 목 앞 | front neck | | NECK | NONE |
| 목 › 목 뒤 | back neck | | NECK | NONE |

  `push_pull`은 분석에 쓰이지 않고 종목 상세의 "동작" 줄에만 보인다 — 기본 종목에서 그 부위에 가장 많은 값을 쓴다.
- `group_name`: 계열 안에서 만들면 그 계열 이름(그 부위에 실제로 있는 계열인지 서버가 확인), 아니면 null.
- `name_en`·`starter_rank`·`common_rank`는 null.
- 탈퇴: `owner_id` 연쇄 삭제. 그 종목을 쓴 세트는 같은 사람의 기록이라 기록과 함께 지워진다. **다만 하루 기록을 먼저 지운다**(`WorkoutSessionRepository.deleteAllOfUser`) — PostgreSQL은 연쇄 삭제를 단계마다 검사해, `users → exercises`가 `users → workout_sessions → workout_sets`보다 먼저 검사되면 아직 남은 세트가 종목 외래키에 걸려 탈퇴가 실패했다(테스트로 재현). 처음에는 "문장 끝에 검사해 순서 문제가 없다"고 적었는데 틀렸다.

## 5. API — 「API 명세서」 5장에 추가

### 5.1 새 엔드포인트 (로그인 필요)

| 메서드 | 경로 | 하는 일 | 응답 |
|---|---|---|---|
| POST | `/exercises` | 만들기. 숨긴 내 종목과 이름이 같으면 그 종목을 되살려 값을 바꾼다 | `201` 종목 |
| PUT | `/exercises/{id}` | 고치기 — 내 종목만. 만들기와 같은 본문 전체 | `200` 종목 |
| DELETE | `/exercises/{id}` | 기록 없으면 지우기, 있으면 숨기기 — 내 종목만 | `204` |

요청 본문(POST·PUT 공통 — 고치기 창도 값이 다 채워진 채 열리므로 고칠 때도 전체를 보낸다):

```json
{ "nameKo": "케이블 Y 레이즈", "category": "SHOULDERS_FRONT", "side": null,
  "equipment": "CABLE", "measureType": "WEIGHT_REPS", "groupName": "레터럴 레이즈" }
```

- `side`: `FRONT`·`BACK`. `category`가 `LEGS`(앞허벅지·뒤허벅지)나 `NECK`(목 앞·뒤)일 때만, 그때는 필수. 예전 이름 `legSide`도 받는다.
- `groupName`: 선택. 그 부위의 계열이 아니면 `400`.
- 오류: 이름이 비었거나 50자 초과·부위/기구/기록 방식 누락·하체·목인데 `side` 없음·없는 계열 → `400 VALIDATION_ERROR`, 이름 겹침 → `409 EXERCISE_NAME_TAKEN`(새 코드), 100개 초과 → `409 EXERCISE_LIMIT_EXCEEDED`(새 코드), 남의 종목·기본 종목을 고치거나 지움 → `404`.

### 5.2 바뀌는 기존 API

- **종목 응답에 `mine: boolean`** 을 더한다(5.2 목록, 5.3 단건 등 종목을 돌려주는 모든 곳).
- **보이는 범위:** 종목 목록·분류 수·계열 수·단건·즐겨찾기·직전 기록·종목 기록·1RM 추이(7.1)는 **기본 종목 + 내 종목(숨긴 것 제외)** 만. 남의 내 종목 id는 `404`(있는지조차 드러내지 않는다 — 1.3과 같은 원칙). 비로그인은 기본 종목만(조회는 지금처럼 로그인 없이 열려 있다).
- **`GET /exercises/groups`(5.7):** 계열의 수에 그 계열 안의 내 종목을 더한다. 계열 없는 내 종목이 있으면 끝에 `{ "groupName": null, "mine": true, "count": N }` 한 칸 — 화면은 이것을 "내 종목" 가로 칸으로 그린다. 그 목록은 `GET /exercises?category=…&ungroupedMine=true`.
- **세트 저장(6.4):** 남의 내 종목이나 숨긴 내 종목이면 `404`.
- **루틴(11장):** 후보·교체 후보에서 내 종목을 뺀다. 교체(11.6)에 내 종목 id를 보내면 `400`("직접 만든 종목은 루틴에 넣을 수 없어요").

## 6. 다른 기능과의 관계

- **분석·회복·1RM:** 손대지 않아도 들어간다(종목 id → `primary_muscle`). 부위를 고치면 지난 기록도 새 부위로 계산된다.
- **루틴:** 결정 8. 운동 리마인더 문구도 루틴 계산이라 영향이 없다.
- **그룹:** 친구 기록에 이름만 보인다.
- **붙여넣기(4번):** 미리보기에서 우리 DB에 없는 종목은 이 만들기 창을 연다. 이름은 글 그대로, 기구는 이름에 붙은 말("핀 머신" → 머신, "케이블" → 케이블), 기록 방식은 세트 줄(kg가 있으면 무게 × 횟수, 없거나 "맨몸"이면 횟수만)로 미리 채운다. 글의 이름이 기본 종목 이름과 똑같으면 만들지 않고 그 종목으로 맞춘다(결정 10과 같은 비교).
